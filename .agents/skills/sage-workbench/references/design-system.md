# 视觉规范

## 配色和字体

| 用途 | 值 |
| --- | --- |
| 画布 / 内容面 | #f7f8f5 / #ffffff |
| 项目侧栏 / 图标栏 | #eff3ed / #e6ece4 |
| 主文字 / 次要文字 | #203e34 / #68796f |
| 主操作 / 悬停 | #204b3c / #30634d |
| 分割线 / 控件边框 | #dfe5de / #cbd6cd |
| 选中底色 / 焦点 | #e1ebdf / #568165 |
| 成功文字 / 背景 | #38734a / #e9f2e7 |
| 警告文字 / 背景 | #8a692e / #faf4e6 |
| 错误文字 / 背景 | #a34638 / #fbefeb |

UI 用系统 sans-serif；Windows 优先 Segoe UI、Microsoft YaHei。代码用 Cascadia Code、Consolas、monospace。页面标题 28px/1.45、区域标题 17px/1.5、正文 14px/1.8、表单标签 13px、帮助说明 12px。10px 等宽英文眉题仅用于辅助信息。颜色不是状态的唯一提示。

## 布局

有两级项目结构时采用 C 壳层：64px 工作区图标轨道、256px 项目任务栏、剩余宽度主内容。平板可用 60px + 220px；600px 以下改顶部横向图标栏和紧凑任务区。任务列表独立滚动，移动端建议限高 200px。长项目名截断但保留可访问的完整名称。

顶部使用简洁面包屑，主内容左右 32px，表单内容上限 800px。手机左右 16–20px。标题与表单间距 24–28px，卡片内边距 24px，卡片之间 20px。窄屏卡片内边距 16–20px。

没有多工作区概念时沿用适合产品的单侧栏或其他原导航；保持颜色和密度，不凭空增加项目层级。

## 表单

- 分区白底、1px 边框、12px 圆角；标题、可选短说明、可选编号或线性图标。
- 短且相关的字段可双列（渠道/类型、模型/思考强度），窄屏单列；路径、Cookie、正文全宽。
- 原生 input/select 与库内搜索选择器均为 40px 高、8px 圆角、14px 字号。textarea 最小 88px，可垂直缩放。
- 表单项间距 20px；label 与控件 8px；控件与 helper 8px。helper 不用负 margin。错误出现后顺序推开下方内容。
- 输入、只读、禁用、加载、错误和空结果尺寸一致，避免跳动。下拉列表保留明显选中态。
- 上传区域用轻底色、虚线边框、选择按钮、格式/大小说明、预览及移除操作。不画未实现的拖放交互。
- 主操作深绿填充、次操作白底边框、刷新等轻操作透明底。独立保存区域各自保留操作和反馈。

## 列表与状态

分组标题 12px，含折叠指示和低对比数量。选中任务用浅绿底和轻边框；标题最多两行，手机一行截断。图标 15–18px。

类型与人工进度用小型文字标签，自动执行状态使用独立次要文字/状态点。未知或异常状态不得伪装成功。

参考项目类型为「需求 / Bug / 其他」，进度为「进行中 / 待验收 / 待合并 / 已完成 / 已搁置」。它们是参考项目业务定义，不是其他产品必须使用的枚举。

## 会话与资料

顶部标题与动作对齐，人工分类/进度放紧凑工具栏。会话 ID、分支、路径收进资料折叠区；长 UUID 不作主标题。

时间线和输入框对齐到约 800px 阅读列。用户消息浅绿底；助手消息清晰标角色；工具记录用可折叠白色细边框块。代码区浅灰绿、12px 等宽字，可换行或局部滚动。

需求正文、表格、附件、提示词保持安全渲染；视觉重构不能把外部文本转为无约束 HTML。内容和输入框各有合理滚动边界。

## 弹窗与反馈

弹窗宽约 460px，上限 calc(100vw - 32px)，最大高 calc(100dvh - 32px)，内部滚动。白底 16px 圆角、轻阴影、半透明绿灰遮罩。标题与关闭同排，底部操作分割线。保留 Escape、初始焦点、焦点限制、关闭后返回焦点。

图标选择器含预览、搜索、五列 SVG 网格、选中态、恢复默认和空结果。持久化由项目决定。

空状态用小型线性图标、标题、短说明和一个主操作；不加营销插画、虚构指标或不存在的入口。反馈用淡色背景与文字表达真实结果。

## 验收

- 检查 1440、768、390px；长标题和关键操作再检查 320px。
- 页面、卡片、表单无意外横向滚动。图标栏、代码、表格可按需局部滚动。
- 通过实际尺寸验证说明未覆盖控件、弹窗按钮可到达、错误不遮挡下一字段。
- 检查 focus-visible、对比度、加载/只读、下拉弹层、缩放、reduced-motion。
- 用示例数据截图，保留项目测试要求，不运行真实需求或修改外部业务系统来做视觉验证。
