# 浅绿工作台统一风格

这是用户选定的 C 方案：浅绿双侧栏、米白画布、白色内容卡片和深绿主按钮。把同一视觉语言应用到完整产品界面，而非只调整一个页面的颜色。

## 使用流程

1. 先读项目约束与当前页面结构，列出页面、弹窗、重要交互状态。保留既有业务含义、权限和数据行为。
2. 阅读 [视觉规范](references/design-system.md)，按需查看 [原型索引](references/prototypes.md)。图片用于理解层级和风格；数值、文案、状态和功能以真实需求为准，不复制生图产生的虚构字段。
3. 在项目建立共享设计变量和组件。可复制 [CSS 变量](assets/design-tokens.css) 作为起点；把组件库主题同步到这些变量。不要为每页叠加另一套颜色、尺寸或负边距补丁。
4. 统一壳层、标题、表单分区、列表、状态标签、操作区、弹窗与反馈。页面结构随产品调整；只有存在多项目与项目内任务这两层导航时才采用双侧栏。
5. 使用项目要求的构建和回归测试，并用假数据检查桌面、平板、手机、长文本和错误状态的截图。检查溢出、遮挡、焦点、键盘与弹窗滚动，不能仅凭构建通过就宣称视觉对齐。

## 核心约定

- 米白背景、浅绿导航、白色表面、深绿主操作。语义颜色用于状态，不用装饰性渐变或大阴影。
- 8px 间距基准；40px 表单控件；8px 控件圆角、12px 卡片圆角、16px 弹窗圆角。普通正文 14px、帮助文案 12px。
- 标签、控件、说明、错误信息垂直排列，说明与控件至少 8px 正间距。组件库和原生控件要在同一基线上。
- 表单使用清晰的标题和白色分区卡片；长表单自然滚动，不缩小字体来强行塞进一屏。
- SVG 线性图标采用项目现有组件库；在没有现成库时选一套一致的组件库。不要用 emoji 替代操作图标。
- 人工业务进度与自动执行状态分开呈现；业务状态由产品定义，本技能不自行创建状态或更改流转。
- 响应式导航只调整呈现方式，不改变当前项目、选中任务或后台执行。

## 原型生成与交付

普通样式调整直接使用现有参考。用户要求新的生图原型时，使用可用的 imagegen 能力并沿用规范；先生成参考，再对齐实现。不要把 HTML 截图称作 AI 生图，也不要为了生图把真实配置或敏感内容发给外部接口。

原型集合见 [8 张原型与适用页面](references/prototypes.md)。报告时区分「生成原型」与「实现截图」，注明已验证的页面和未覆盖状态。
