# Web Coding 界面规范

本 Skill 是随仓库分发的界面实施入口，不依赖开发者个人目录中的 Skill。使用前读取 [UI 契约](../../../docs/engineering/ui-design.md)、[前端边界](../../../web/src/README.md) 与受影响组件；结构和依赖调整同时遵循 [工程规范](../web-coding-engineering/SKILL.md)。用户明确指定的设计及项目品牌规范优先。

## 复用现有设计

- 设计变量以 [design-tokens.css](../../../web/src/shared/styles/design-tokens.css) 为准，公共布局和状态以 [style.css](../../../web/src/shared/styles/style.css) 为准。先寻找已有组件和变量，不复制另一套页面级主题。
- 保持浅绿导航、米白画布、白色卡片和深绿主操作；错误、警告、成功颜色表达实际状态。保留现有 SVG 图标体系。
- 表单统一标题、分区、标签、控件、说明和错误反馈。说明保持正间距，长表单正常滚动，错误不能覆盖下一个字段。
- 任务类型、人工进度、Codex 执行状态和渠道状态分开呈现。不得因视觉简化推断任务已完成或修改业务状态。
- 登录、改密、账号管理与个人设置归 `features/accounts/`，其他功能归对应 feature；app 组合路由、账号和工作区，不承担表单内部业务。

## 交互与隔离

- 加载、保存、失败、空状态、禁用和只读状态都需明确；相关操作使用独立状态，避免检索结束释放仍在进行的启动或保存锁。
- 保留账号、工作区、任务切换的身份与代际判断，卸载后清理监听、订阅和对象 URL；迟到请求不得恢复已清空草稿或写入新账号。
- 统一原生控件和组件库控件的高度、字体及焦点样式；输入、只读和禁用状态不应产生布局跳动。
- 弹窗支持键盘、Escape、焦点恢复和可到达的底部操作；删除类操作保留项目约定的明确确认步骤。
- 需求富文本走 `shared/components/markdown-content.js` 安全基础；会话仍经 `features/session/requirement-content.js` 保留原有约束。项目正文使用 `MarkdownContent`／`MarkdownEditor`，不能为了展示改成未过滤 HTML 或加载任意远程图片。
- 响应式改变呈现方式，不改变当前工作区、选中任务或后台执行。

## 验证

根据任务覆盖受影响页面的正常、加载、失败、长文本和窄屏状态。桌面、平板、手机参考 1440、768、390px；关键按钮与弹窗额外检查 320px。确认无意外横向溢出、控件遮挡、说明重叠和不可达操作。

完成工程规范要求的 lint、测试、构建和浏览器回归。布局、样式或组件位置调整运行 `npm run test:visual`；查看 [模拟数据截图索引](../../../state/browser/unified/index.html) 中本次生成的相关截图，不能仅凭构建成功宣称视觉验证通过。索引由命令生成，未生成前无需存在。

账号页面的截图由 `npm run test:web` 中的账号回归生成在 `state/browser/accounts/`；修改登录、改密、个人设置或账号管理时，查看这些页面的本次截图，不能用工作台截图代替。

截图仅使用假数据和临时环境，不执行真实需求或修改 TAPD。生成参考图与实际页面截图分开标记；普通界面调整不要求重新生成原型。
