# Web Coding · 需求开发工作台

Node.js 22.13+、Vue 3 的需求开发工作台，使用 Fastify 和 SQLite。**每个成员拥有私有工作区，一个工作区对应一个项目和一套独立配置**，支持 TAPD 需求和手动图文需求；每个任务拥有独立 Git worktree 与持久化 Codex 会话。

## 开始使用

需要 Node.js 22.13+、npm、Git，以及已安装并登录的 Codex CLI（`codex login`）。

```sh
npm ci
npm run init:admin
npm run build
# 已构建时，默认监听所有 IPv4 网卡
npm start -- --port 4317
# 仅允许本机访问
npm start -- --host 127.0.0.1 --port 4317
```

初始化管理员时交互输入密码，服务与账号命令必须使用同一个 `RUNNER_DATA_DIR`。本机打开 `http://127.0.0.1:4317` 登录。管理员在「系统设置」配置成员项目与任务目录的基础路径，并在「账号管理」创建成员。成员先在「个人设置」维护 Git 账号（系统生成的 SSH 密钥或 HTTP/HTTPS 账号密码／令牌），创建工作区时选择账号并输入远程地址，服务直接克隆项目。其他成员和管理员不能通过页面或 API 查看其私有工作区。

最左侧的图标栏用于切换工作区，悬停可查看完整名称，点击「＋」新建工作区。相邻侧栏显示当前项目和需求列表，项目名旁的齿轮图标打开工作区设置，在「基本信息」中点击「重命名」可编辑名称和图标。点击「选择图标」打开独立弹窗，可搜索 40 个常用 SVG 图标（支持中英文关键词），也可恢复为名称首字；表单默认只显示当前图标预览。窄屏时图标栏变为顶部横排。工作区选择保存在页面 URL，刷新后保留，不同浏览器标签页可以同时使用不同工作区。切换不会停止原工作区的后台任务。每个工作区只显示自己的会话、需求资料和附件。

创建工作区会立即提交后台克隆任务。顶部「克隆任务」显示连接、下载、整理和检出等阶段及 Git 实际报告的阶段百分比；等待远端响应时显示不定进度。受理后关闭弹窗、刷新、关闭浏览器或退出登录都不会停止克隆，再次登录可恢复查看，完成后点击「打开工作区」。每个账号最多同时克隆 3 个项目，同一请求重试不会重复克隆。服务停止或重启会中断克隆，不会自动重试；异常退出留下的目录需管理员确认，不会自动覆盖或删除。大仓库允许最长 6 小时，连续 30 分钟无 Git 输出会超时。


工作区切换在页面内完成，不重新加载网页；加载期间保留工作台布局并显示提示，可继续切换其他工作区。浏览器前进、后退同步工作区选择。切换会清空当前未发送的草稿并停止尚未开始的图片上传，不影响已经启动的后台任务。修改工作区名称或图标时保留当前页面和草稿。

这是全新的数据库结构，**不迁移或读取旧的工作区配置、runs 和 uploads**。旧资料和业务 Worktree 保留原位。本次没有自动清理或重新执行旧任务。

## 账号与三层设置

- 「个人设置」由成员本人维护：Git 账号、通知开关、默认任务分组、默认模型、思考强度和执行权限，适用本人全部工作区。
- 「系统设置」由管理员维护：所有成员共用的成员项目与任务目录基础路径，并显示 Git 环境检测结果。
- 「工作区设置」由所有者维护：自动生成的项目目录、基准引用、初始化命令、TAPD 配置和提示词模板。

成员初次使用管理员分配的密码时须改密。退出或密码重置撤销登录和实时连接；已启动任务继续运行。管理员可在「账号管理」重置成员密码。浏览器通知授权仍由设备管理。

## 本地开发与即时更新

开发时使用已有的 Vite，无需增加依赖或每次重新构建：

```sh
# 前端热更新，后端保持运行
npm run dev
# 前端热更新，并在后端源码修改后自动重启
npm run dev:watch
# 可选：局域网访问或自定义端口
npm run dev -- --host 0.0.0.0 --port 5173
```

默认打开 `http://127.0.0.1:5173`。Vue、CSS 和前端模块保存后自动更新；部分模块变更会刷新页面。页面、API 和 SSE 共用同一端口，不需要另外启动 `npm start` 或配置代理。`dev` 模式修改后端后需手动重启；`dev:watch` 监听 `src/` 的 CJS 和 `shared/` 的 JSON，先关闭旧服务，再启动新服务，连续保存会合并处理。自动重启通过进程消息完成，兼容 Windows 和 Linux。

**后端重启会停止初始化和正在执行的 Codex 轮次，并自动刷新开发页面。** 已有会话身份、历史、执行设置和 worktree 保留，之后可在原会话继续；不会自动重跑需求。重启刷新会清空页面中未发送的草稿。实际任务运行期间建议使用 `npm run dev`，只热更新前端。

开发服务默认仅监听本机；HTTP 和热更新连接继续校验 Host/Origin，写接口仍需页面令牌。开发源码访问限于 `web/`、`shared/` 和依赖目录，不开放工作区数据目录。两种模式都沿用 `RUNNER_DATA_DIR`；需要独立开发数据时，将其设为单独目录，不要与另一个运行中的服务同时操作同一工作区。

正式使用先运行 `npm run build`，再用 `npm start` 启动服务。仅更新正式版前端时，重新构建后刷新页面即可，无需重启后端。

## 系统设置

点击工作区栏底部的「系统设置」，配置「成员目录基础路径」。这是所有工作区共用的服务端绝对路径，默认 `~/.codex-workspaces`，可手动输入或点击「浏览服务器目录」选择服务端已有目录。Windows 支持切换磁盘；目录选择器也支持进入子目录、返回上级和输入路径。不读取浏览器所在电脑的目录，也不上传文件。手动填写的新目录会在保存时创建并检查写入权限，同时显示服务器是否已安装 Git。

创建工作区时，服务按所选 Git 账号克隆远程地址到「系统基础目录／用户名／projects／项目名」，例如 `/srv/wt/alice/projects/project-a`。任务 Worktree 位于「系统基础目录／用户名／worktree／项目名」，例如 `/srv/wt/alice/worktree/project-a`。项目名从远程地址生成，不允许手填仓库或目录。账号名统一为小写且全局唯一，当前不提供账号改名；特殊名称由服务端转换为兼容的目录名。

## Git 账号与连接检测

在「个人设置 → Git 账号」填写完整仓库克隆地址，不能只填 Git 服务首页。HTTP 和 HTTPS 均支持普通用户名与密码，也可使用 Git 服务支持的个人访问令牌。HTTP 不加密传输凭据，仅建议用于可信网络的开发环境。

SSH 账号点击「生成 SSH 密钥」，将展示的公钥复制到 Git 服务的 SSH 密钥设置。私钥由服务器加密保存，不回显、不接受手工填写；服务器需安装 OpenSSH（`ssh-keygen`）。未保存的密钥草稿有效期为 24 小时，再次生成会替换旧草稿，不影响已保存密钥。

「测试连接」只检测当前草稿；「检测并保存 Git 账号」强制使用当前草稿检测，成功后才保存。修改 HTTP 账号时密码留空保留原值。失败保留原账号与界面草稿。检测验证仓库读取权限，不代表推送权限；被工作区使用的账号不能删除或切换 HTTP／SSH 认证方式，但可以更新同类型的密码、令牌或密钥。克隆、后续 fetch，以及该工作区中 Codex 发起的 Git 网络操作均使用所选账号；凭据不写入远程 URL 或仓库配置。HTTP 凭据仅作为该工作区 Codex 子进程的 Git 配置传递，SSH 私钥仅在受限临时文件中保留至该子进程关闭。

更新 Git 凭据不会中断正在执行的轮次或审批。工作区全部轮次、启动及命令操作空闲后，下次启动任务或续聊会自动重连并读取新凭据，保留原 session 和 Worktree；异常断线重连也重新读取，无需重启服务。Codex 使用隔离认证配置，同时从服务用户的系统／全局 Git 配置中保留提交身份默认值（`user.name/email/useConfigOnly`、`author.name/email`、`committer.name/email`），仓库自身配置仍可覆盖这些默认值；没有配置身份时不会自动伪造作者。

本次 Git／目录配置重构不兼容旧数据与旧字段，不提供自动迁移或回退。请使用新的独立数据目录部署；程序不会删除旧数据库或移动旧项目、任务目录。

## 工作区设置

每个工作区只有一个目标仓库，所有渠道共用这个项目，不使用按 TAPD 项目映射的多仓库设置。

- 仓库与 Worktree 目录：创建工作区时由远程 Git 地址自动生成，只读展示；服务端不接受工作区设置页修改。
- 基准引用：默认 HEAD，可选择本地分支、远程跟踪分支、标签或填写 commit SHA；选择器只读本地 refs，不执行 fetch 或 checkout。
- 初始化命令：每行一条，最多 20 条、每条 4000 字符、每条超时 15 分钟。Windows 使用 cmd，Linux 使用 sh。每条从新 worktree 根目录开始，互不继承 `cd` 和环境变量修改；例如 `pnpm install`、`pnpm build`。

保存只影响新任务；已有任务继续使用记录的 session、路径和分支。初始化失败、超时或停止后不启动 Codex、不修改渠道状态，保留目录和日志用于排查。不会自动重跑不确定的初始化或已有任务。

### 提示词模板

在「工作区设置 → 提示词模板」中，分别维护手动需求和 TAPD 需求的启动提示词。每个工作区独立保存，修改仅对当前工作区的新任务生效，无需重启；已有任务的需求快照、实际提示词和后续会话保持不变。未配置时沿用内置提示词，也可点击「恢复当前渠道默认模板」后保存。

使用 `{{名称}}` 占位符自动填入本次需求，界面提供占位符插入、说明和示例预览。两种模板均须保留 `{{title}}`（标题）、`{{content}}`（需求正文）、`{{images}}`（图片说明与有序列表）；TAPD 模板还须保留 `{{supplement}}`（完整补充说明块，无补充时为空）。可选 `{{image_count}}`、`{{image_list}}`，TAPD 另提供 `{{id}}`、`{{workspace_id}}`、`{{url}}`。例如手动模板：

```text
请根据以下需求完成开发，遵循仓库 AGENTS.md，运行检查并报告结果。
未经用户要求不要提交、推送或发布。
标题：{{title}}
--- 需求资料开始 ---
{{content}}
--- 需求资料结束 ---
{{images}}
```

每个模板最多 20000 字符；空模板、未知或未闭合的占位符、缺少必填占位符会阻止保存。替换仅进行一次，需求正文中的占位符文本不会再次展开，不支持表达式或脚本。图片仍作为附件按顺序传入，预览使用示例数据。

模板保存在 SQLite 的工作区设置中，保存时保留仓库和渠道配置。CLI 通过 `--app-workspace` 选择同一工作区模板；显式 `--config` 使用所选文件中的模板。

## 在 Web 维护 TAPD

在工作区设置的「TAPD 渠道」中填写：

1. TAPD 项目 ID：与应用工作区 ID 不同，一个应用工作区绑定一个 TAPD 项目。
2. 包含 `dsc-token` 的完整单行 Cookie。
3. 可选额外图片域名，每行一个完整主机名。

「检测连接」用当前填写的 Cookie 和项目调用只读待办接口；Cookie 留空时使用已保存值。检测展示成功或失败，**不保存配置、不启动 Codex、不修改需求状态**。即使待办为空也能检测。网络异常、过期登录或接口拒绝会提示检测失败。

「保存 TAPD 配置」保存后立即生效，无需重启。Cookie 加密入库且不会回显；留空保留原值，粘贴新值替换，也可勾选清除。数据库和独立主密钥请勿提交到 Git。手动需求不需要 TAPD 配置。

「从需求启动」中检索当前 TAPD 项目的全部待办（需求、缺陷和看板卡片），不按开发中状态码过滤，也不沿用旧会话中的视图筛选；仍可按标题检索或直接填写需求 ID（默认需求类型）。当前工作区已有且人工进度为“进行中”的任务显示“本系统进行中”，其他已有任务显示“本系统已有任务”；已有记录仍拒绝重复启动，请从任务列表打开原会话。TAPD 项目绑定在设置中维护，启动表单只读显示，服务端也拒绝跨项目请求。启动和继续执行均不自动修改 TAPD 状态或人员字段，无需选择开发/测试人员；旧 workflow 配置不再生效。

可在「补充说明（可选）」中填写需求细节、验收标准或指导意见，最多 60000 字符。补充说明随原需求一起发送给 Codex，并保存在本次任务的需求详情中，不修改 TAPD 原需求；留空仍按原需求执行。切换渠道、项目或需求 ID 时清空补充说明，避免带入其他需求。

## 每个需求的模型、思考强度与权限

在「从需求启动」中为本次需求选择 Codex 模型和思考强度，TAPD 与手动需求均适用。每次新建需求使用当前成员的个人默认值；未设置模型或强度时沿用 Codex 默认配置。每个任务可独立选择，模型列表实时读取服务端 Codex，加载失败可刷新重试并保留当前选择。

选择具体模型后，思考强度下拉框只显示该模型支持的选项，也可使用默认强度。切换模型会清除不支持的强度。工作区不再设置模型或思考强度，旧工作区中的这两项不影响新任务。

创建需求时同时选择权限，初始值来自个人设置；未修改个人设置时为「请求批准」：

- 请求批准：使用工作区写入沙箱，写入工作区外文件或访问网络时按需请求用户批准。
- 帮我批准：使用同样的沙箱，由 Codex 原生自动审查权限请求，根据风险决定是否批准；当前 Codex 不支持或能力检查失败时禁用，并显示原因。
- 完全访问权限：关闭 Codex 沙箱与逐次审批，允许访问网络和本机文件。仅在信任当前任务时选择。

会话输入框左下可修改权限，右下可修改模型与思考强度，选择后立即保存。执行中修改会显示「下一轮生效」；本轮补充指令继续使用本轮设置，结束后发送的新消息使用新设置。修改不创建新会话或 worktree，也不会处理已有审批。刷新、重连与服务重启后保留选择；切回默认模型或强度时，下轮会重新读取适用的默认值。初始化中和只读任务不可修改执行设置。

## 手动图文需求

选择「手动输入」，填写标题和 Markdown 内容，可附 PNG/JPEG/WebP 图片，最多 20 张、每张 10 MiB；支持仅标题加图片。上传和运行记录都按应用工作区隔离，不能引用另一个工作区上传的图片。未使用的暂存图片 24 小时后过期，在后续上传时清理。

任务目录由「前缀＋12 位任务短标识」组成。前缀默认按标题生成，英文保留、中文转无声调拼音，最多保留 16 位。可填写「Worktree 目录前缀」，只支持 1–16 位英文字母、数字、短横线或下划线，以字母或数字开头，排除 Windows 设备名；不能传路径，系统始终追加短标识，不会覆盖已有目录。

## 类型标签与任务进度

创建任务时可选择「需求 / Bug / 其他」类型，已有任务可在右侧「信息」抽屉修改。左侧列表显示类型标签和进度，支持按类型分组、按进度分组或不分组；分组可折叠，分组方式保存到个人设置，适用本人全部工作区。

会话标题独占一行，长名称自动换行，执行状态与刷新位于下方，任务管理与归档、删除位于右侧「信息」抽屉。点击编辑图标可在完整宽度的输入区修改标题（最多 200 个字符），Enter 保存、Escape 取消；中文输入法选词不会触发保存。标题会保存并同步到同一工作区的其他已打开页面，仅作为会话展示名称，不会修改原始需求快照、session、分支或 Worktree 路径。TAPD 详情兼容 `name` 与 `title` 字段；历史空标题显示「未命名会话 · 需求 ID」，可手动改名。

左侧列表下方的「已归档会话」可查看当前工作区的归档记录、按名称搜索、恢复或直接删除，无需先恢复。恢复后会话重新出现在需求列表，保留原有历史、会话身份和代码状态，不会自动重新执行任务；已删除的 Worktree 不会重建。删除复用会话页面的确认流程，仍有关联代码时可确认分支名后强制清理。永久删除的会话无法找回。

会话可归档或永久删除。归档后不再出现在左侧列表，但历史、需求资料和 Worktree 保留。永久删除会移除会话记录、需求资料和附件，无法恢复。有关联代码时，可先通过 Git 面板清理，或勾选「同时强制删除 Worktree、本地目录和本地分支」，输入完整本地分支名并确认后一次清理。强制删除会放弃未提交、未跟踪、忽略文件和未推送的本地提交，也会清理原任务目录中的残留文件；远程分支保留。运行中、有待处理审批、其他服务占用或目录身份不符时不能删除；清理失败保留会话和删除进度，可重试。

新任务默认为「进行中」。人工进度提供「进行中 / 待验收 / 待合并 / 已完成 / 已搁置」，在右侧「信息」抽屉选择后立即保存。Codex 的执行、停止、单轮结束和重连续聊均不自动修改人工进度，执行状态会另外显示。修改类型或进度只更新本地任务管理信息，不修改 TAPD 状态。

旧任务尚未标记时默认显示「需求、进行中」（原始类型为 Bug 的显示 Bug），可以随时手动调整；不会根据历史执行结果自动认定完成。

## Git 和会话

新任务创建的 worktree 位于：

```text
<成员目录基础路径>/<用户名>/worktree/<项目名>/<任务前缀>-<12 位任务短标识>
```

例如 `D:\wt\alice\worktree\project-a\login-a1b2c3d4e5f6`。任务目录最多 29 位，不再叠加仓库哈希目录或重复的工作区 UUID。分支为 `codex/<12 位任务短标识>`，短标识由仓库真实路径、完整工作区 ID 和需求来源身份共同生成，不受标题或自定义前缀变化影响。同名任务仍保持隔离；目录或分支已存在时拒绝创建。

用户名目录仅用于新任务。已有任务继续使用记录的 session、分支和 Worktree 路径，包括旧的 `u-<成员 UUID>` 目录，不重命名、不搬移。

Windows 创建前会检查目标提交中的文件和目录路径长度，过长时显示具体路径并提示缩短系统基础目录或工作区目录，在创建分支及检出文件前停止。建议基础目录使用 `D:\wt` 等短路径，为仓库内部目录留出空间。该检查覆盖 Git 已跟踪内容，依赖安装和构建生成的文件仍受系统路径限制。

根仓库不会切换分支、stash、提交或带入未提交的更改；不会复制 `.env`、Cookie 或 node_modules。任务结束保留 worktree。服务不会自动合并、推送、删除分支或验收需求。

点击左侧工作区名称下的「代码仓库」可管理 Git 更新。「获取远端更新」使用已配置的远端刷新远程跟踪分支，不改变已有任务代码。「更新基准分支」会先获取其上游，再仅以快进方式更新；要求基准是仓库当前检出的本地分支、已配置远端上游且目录干净。若分支分叉、存在本地修改或 Git 操作未结束，会提示原因，交由 Codex 或本地工具处理。选择远程引用、标签或 SHA 作为任务起点时，仍可获取远端更新，但不会直接修改该引用。网络操作使用工作区关联的个人 Git 账号，不弹出登录窗口。

右侧「Git」入口打开 Worktree 抽屉，显示未提交文件、待推送提交和落后远端数量；可查看当前实际检出的分支、路径及上游。未提交文件包含已跟踪修改与未跟踪文件，忽略条目另列。提交数量与当前分支的远端上游比较；没有上游显示「分支尚未发布」，读取失败显示未知，不当作 0。状态在打开会话、任务状态变化或手动刷新时读取；远端比较基于最近获取的本地记录。任务记录的初始分支不因目录内切换分支而阻止继续会话，但删除 Worktree 仍要求回到记录分支并完成该分支的确认。合并和冲突处理由会话中的 Codex 完成，界面不提供合并或冲突处理按钮。

Git 面板提供「删除 Worktree 与本地分支」：展示任务目录、完整分支名及风险，需要输入分支名确认；有未提交、未推送、尚未发布或忽略内容时，还须确认丢弃本地内容。运行中、其他服务占用、Git 操作进行中、目录身份不符或确认后状态变化都会阻止删除。只通过 Git 删除登记的任务 Worktree 和对应本地分支，不删除远程分支。目录删除成功而分支删除失败时保留进度，刷新后可重试分支清理。删除后会话历史、需求资料和记录保留，任务转为只读；人工进度保持原值。

Web 使用 `codex app-server --stdio`，按任务选择设置审批与沙箱。需由用户处理的命令和文件审批、澄清问题在页面显式显示。输入框可发送后续指令，执行中可补充指令或停止当前轮；始终沿用原 session。关闭浏览器不停止任务；正常关闭服务会请求中断活动任务，重启后可继续。

会话输入框支持直接粘贴剪贴板中的截图或图片（Ctrl + V），也可点击权限左侧的「＋」选择文件。发送前可预览、移除，支持图文一起发送或仅发送图片；执行中也可补充图片。每条消息最多 20 张 PNG/JPEG/WebP，每张不超过 10 MiB。上传完成后可点击发送或按 Enter，Shift + Enter 换行；中文输入法选词确认时不会发送。上传失败可重试，发送失败保留草稿。已发送图片随会话历史展示，并按工作区和任务隔离保存。

Codex 回复按 Markdown 显示，支持标题、列表、加粗、行内代码、代码块、引用、表格和链接；流式回复与历史记录使用相同格式。长代码和表格可在内容区横向滚动。回复中的 HTML 源码按文字显示，Markdown 图片仅显示替代文字；用户消息和工具输出保留原文。

会话详情使用加宽的消息区与输入框。右侧「信息 / Git / 需求」入口按需打开抽屉，默认收起；再次点击当前入口、点击收起、抽屉外区域或按 Escape 可关闭。抽屉独立滚动，不挤压对话区；切换资料保留消息草稿和对话位置。历史消息、命令输出和文件修改在对话区展示，启动时的完整需求快照、图片和实际提示词在「需求」抽屉查看。已移除或未注册的 worktree 只读。记录中的路径是权威值，修改安装路径或设置不会搬动业务 worktree。

## 数据与部署

默认数据目录为应用目录，可用 `RUNNER_DATA_DIR` 指定独立位置。静态资源固定从安装包的 `web/dist` 读取。

```text
<RUNNER_DATA_DIR>/
  db/web-coding.sqlite   # 账号、设置、任务、历史、日志和图片 BLOB
  db/backups/           # 升级前的一致性备份
  secrets/database.key  # TAPD 凭据加密主密钥，需单独保管
  workspaces/           # Codex 图片缓存和必要的执行锁
```

业务数据以 SQLite 为准；图片缓存可重建，Codex 离线也能查看已保存历史。Git／Worktree 和 Codex 自身的引擎资料仍保留文件形式。相关数据目录均加入 Git 忽略；备份 SQLite 时还应单独保管主密钥，恢复执行还需要原有业务目录和 Codex 环境。

CLI 默认监听 `0.0.0.0`，可用 `--host 127.0.0.1` 限制本机。远程部署使用 HTTPS 反代并配置 `PUBLIC_ORIGIN`；应用内的私有工作区不等于操作系统执行隔离，适用于受信任成员。安装说明见 [部署说明](docs/deployment.md)，完整数据、权限和升级契约见 [账号与数据库](docs/engineering/accounts-and-database.md)。

服务启动前自动执行未完成的数据库升级，并只补缺失的生产默认数据。升级前先停止旧服务；升级失败拒绝启动。生产运行和日常操作均通过 Web 页面完成。

## 验证

代码目录与模块依赖见 [模块与目录规范](docs/engineering/architecture.md)。后端按职责分层，前端按功能分组；测试分别位于 `test/architecture`、`test/unit`、`test/integration` 和 `test/browser`，运行命令保持如下。

界面沿用 C 方案，统一视觉规范见 [UI 设计契约](docs/engineering/ui-design.md)。全页面生图原型和提示词位于 `output/imagegen/unified-pages-20260917/`；Jenkins 的视觉检查会生成纯模拟数据的桌面、平板和移动端实现截图，索引为 `state/browser/unified/index.html`。

```sh
npx eslint src test web/src web/vite.config.mjs
node --test test/architecture/*.test.cjs test/unit/*.test.cjs test/integration/*.test.cjs
npm run build
node test/browser/session.cjs
node test/browser/workspaces.cjs
node test/browser/dev.cjs
node test/browser/accounts.cjs
node test/browser/visual.cjs
```

测试使用模拟 TAPD/Codex 和临时 Git 仓库，覆盖工作区隔离、同需求跨工作区执行、凭据维护/检测、需求模型选择、图片及 SSE 隔离、创建/切换/重命名、刷新和移动布局。不会执行真实需求或修改真实 TAPD。Windows 使用本机 Edge，Linux/macOS 使用 Playwright Chromium；截图在忽略的 `state/browser/`。

Windows / Linux 环境准备和双平台 CI 接入见 [平台验证说明](docs/engineering/platform-verification.md)。仓库提供可从 Gitee 检出的 Jenkins 流水线，两端分别安装依赖并运行同一套检查。
