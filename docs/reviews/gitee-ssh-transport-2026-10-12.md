# Gitee 项目仓库与个人 Git 认证方式匹配

日期：2026-10-12。

## 问题与修复

项目填写 Gitee HTTPS 克隆地址、成员选择同站点 SSH 账号时，连接检测及开发空间准备直接比较主机字符串和认证类型，将合法的同仓库组合拒绝为不匹配。

- 域层新增 `resolveAccountRemote`，统一供 Git 账号检测与项目空间准备使用。已匹配的地址原样保留；官方 `gitee.com` 默认端口、标准两段仓库路径允许 HTTPS 与 `git@` SSH 地址双向解析，按成员所选账号使用实际传输方式。
- 不推断其他 Git 服务、企业域名、自定义端口、非 `git` SSH 用户或异常路径的协议映射。HTTPS 不降级为 HTTP；不匹配错误说明账号与项目各自的主机及认证方式。
- 连接检测、克隆、工作区持久化采用相同解析结果，保留项目原始仓库地址。项目设置更新继续使用各成员已准备空间的传输地址，不会把 SSH 工作区地址覆盖为项目填写的 HTTPS 地址。
- 账号仍按所有者读取；准备请求身份、凭据及项目修订复核、归属及权限复核保留。未修改业务项目、密钥或已记录目录，不自动启动克隆或真实开发任务。
- 开发空间账号选项显示认证方式；SSH 主机说明明确使用 `gitee.com`，不填写 `git@` 或仓库路径，并说明 Gitee 等价地址仅适用于默认端口。
