# 交互与权限修复记录 · 2026-10-10

对应[交互审查](./interaction-review-2026-10-10.md) F01–F12 和 D01–D05。用户补充的主要问题是“部门与项目重复配置，关系不清楚”，本次据此区分两层界面，不改变部门上限与项目授权取交集的规则。

## 权限分配

- **部门可用功能**：系统管理员按六类能力设置上限——项目管理、需求与 Bug 协作、代码操作、Codex 开发、普通资产、敏感资产。默认显示能力卡，细项折叠。开启部门能力不会自动给项目成员加权限。
- **项目分工与授权**：负责人选产品协作、代码操作、Codex 开发、项目管理等组合，预览保存后的有效功能；添加组合保留已有管理权限。部门未开放组合核心功能时禁用添加并说明原因。
- 新成员默认包含查看项目；后端拒绝活跃成员零查看权限。候选不再包含已参与或历史成员，已移除成员通过明确的恢复入口复用关系和空间。
- 创建资格与实际创建的负责人权限前提一致；首次管理员有准备清单，新项目有配置本人及成员分工引导。给自己授权后，项目导航立即刷新。

## 审查问题闭环

| 项目 | 修复与验证 |
| --- | --- |
| F01 错误会话 | 明确指定 runKey 时只读取该对象；不存在显示错误，归档按原对象展示。归档/删除事件也不会把指定对象替换为第一条任务。模拟 API 浏览器验证未读取另一任务。 |

| F06 错误设置页 | 空项目工作台显示“尚无开发任务”，直接进入项目事项，不再打开旧个人工作区设置。 |

| F11 资产历史 | 使用独立分页状态与更早/较新修订按钮，超过 30 条可访问历史页。 |

| D02 开发主流程 | 项目一级入口区分“开发任务”和“代码与环境”；事项详情可直接启动。首次准备保留事项/批量选择，Git 设置有返回环境入口，准备后仍须明确启动。 |
