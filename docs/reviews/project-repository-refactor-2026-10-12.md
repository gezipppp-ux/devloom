# 项目直接引入仓库：改造与验证

> 本文记录当时的实现与验证；其中的增量迁移已合并到当前全新安装基线，旧数据不兼容、不迁移。部署以 [PostgreSQL 接入](../engineering/postgresql.md) 为准。

日期：2026-10-12。

## 最终行为

- 创建项目直接提交项目名称、部门和 Git 地址；无需管理员预先登记仓库，不在创建时克隆或要求个人 Git 凭据。
- 项目直接保存 `remoteUrl`，删除独立 `Repository` 模型、`repositoryId`、仓库 CRUD、选择接口及导航页面。个人 Git 账号仍由成员维护。
- 项目设置按项目配置权限修改地址；已有开发空间后地址锁定，其他配置仍可正常保存。克隆和 Git 账号检测统一读取项目地址并复核项目修订号。
- 编辑中分配空间会恢复服务器上的仓库地址，保留其他草稿并提示原因；加载最新、三方合并和提交都不能重新引入已锁定的地址。
- 未匹配的 API 返回 404；旧仓库接口不保留兼容处理。
- PRD、README、部署、用户手册和工程契约同步更新。

## 数据库

新增事务迁移 `20261012000000_project_repository`，将已有项目的地址收归 `projects.remote_url`，删除旧外键、列及仓库表，不保留双写或旧模型读取。

隔离 PostgreSQL 回归覆盖多个项目关联同一旧仓库时的地址保留，以及迁移最后一步失败时数据、列和约束完整回滚。既有项目、开发空间、任务身份和代码路径不变。
