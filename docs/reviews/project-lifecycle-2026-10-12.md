# 项目生命周期重构验收

日期：2026-10-12。范围依据[PRD](../prd/project-lifecycle.md)，包含用户补充的需求与 Bug 流程图。用户明确允许更换本地数据库，不保留历史格式兼容。

## 完成内容

- 发布版本可创建、修改、归档和恢复。归档要求事项处于完成／取消节点且开发任务全部结束；编辑、评论、交付、附件和资产关联变更均受后端只读门禁约束。
- 项目分别维护需求和 Bug 流程图，支持节点、连线、坐标、开发资格、操作权限和原因。草稿保存后发布为不可变版本，旧事项继续绑定原版本。发布检查初始节点唯一、全部节点可达且可以到达终态；完成／取消节点不能开发。
- 默认需求主链：规划中 → 开发中 → 待验证 → 验证中 → 已实现，另有拒绝、退回和重开；默认 Bug 主链：待处理 → 处理中 → 已解决待验证 → 已验证待关闭 → 已关闭，另有失败待处理和取消。
- 认领／指派仅生成待开发计划，无需 Git，不创建 worktree 或 Agent 会话。开发执行人独立于事项业务负责人；一个任务仅关联同版本事项，唯一活跃认领记录防止重复占用。
- 执行人从 Git 实时远端列表选择分支后显式开始。启动持久化意图与内容快照，再获取最新 SHA 创建 worktree；等待期间重新验证权限和流程开发资格，失败和结果不明均不自动重放。
- 未开始任务可以编辑、转派或取消；已开始任务须实际空闲且无待处理审批后才能完成／取消。结束后释放认领并禁止原会话继续执行。业务验收与 Agent 执行结果互相独立。
- 项目协作成员能看计划，私有工作区、runKey 和会话详情仅对具有相应权限的执行人公开。追加未指定分支的事项继承任务冻结的基线，不受后来修改的项目默认分支影响。
- 清理固定状态枚举、从事项直接启动的弹窗和生产旧启动路径。工作流图支持键盘移动和图内滚动，四种宽度下可访问表单和底部操作。
