## 实现范围

- 管理员在「系统设置 → 流程编排」统一维护需求与 Bug 两套流程，支持状态、连线、坐标、开发资格、操作权限及必填原因。保存草稿后发布为不可变版本。
- 所有项目的新事项绑定同类型当前系统发布版本；已有事项和开发计划继续依据事项原绑定版本，不因系统发布而切换。
- 项目仅可读取已发布流程，不获得草稿或编辑修订号。事项流转仍检查 `issue.transition`／`issue.accept`，个人工作区及会话隔离不变。
- 删除项目流程配置页面、旧项目流程管理 API、`workflow.manage` 授权及项目流程表。没有路由别名、项目覆盖或运行时旧数据回退。
- 新增独立系统流程服务、存储、响应呈现及 HTTP 适配；流程图移至前端共享组件，系统设置与事项详情共用，保持模块边界。
- 新迁移 `20261012060000_system_workflows` 创建系统表并种入两套默认 v1。普通查询不隐式创建默认数据。迁移遇到旧事项明确拒绝并回滚，不转换或删除旧事项。

- 全量架构、单元和集成测试：523 项通过，0 失败、0 取消、0 跳过。
- ESLint、`git diff --check` 与 `npm run build` 通过，构建仍有现有的大 chunk 提示。
- 新增集成测试覆盖管理员与项目负责人权限、CSRF、撤权、草稿隔离、旧接口 404、跨项目版本共享、首次并发创建、发布保持旧绑定、修订冲突，以及迁移种子、旧权限清理和拒绝旧事项后的完整回滚。
- Jenkinsfile 的 8 个浏览器入口全部通过：session、workspaces、dev、accounts、project-collaboration、development-flows、project-editing、visual。
- 浏览器覆盖系统入口与普通成员隔离、草稿保存及发布、跨项目新事项绑定同一版本、旧事项绑定不变、最新状态名称筛选，以及 1440、768、390、320px 编辑器交互。
- visual 生成 155 张截图；已查看本轮系统流程桌面和 320px 截图，表单、说明及底部操作可达，图内允许横向滚动，页面没有横向溢出。
