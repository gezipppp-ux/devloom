# 项目协作交互审查 · 2026-10-10

后续修复与验证见[交互与权限修复记录](./interaction-fixes-2026-10-10.md)。下文保留修复前的发现与证据。

本次按完整用户流程审查当前实现，覆盖系统初始化、项目创建、成员授权、需求/Bug、评论与交付、资产、开发空间及会话。审查对象包含本轮尚未提交的重构代码，不限于增量 diff。

主要问题是：项目协作流程与旧个人工作区流程尚未统一；权限规则存在，但界面缺少授权解释与准备引导；页面打开、刷新、返回、保存没有一致的状态约定。部分问题会丢弃草稿或让用户操作错误的会话，应先于视觉调整处理。

本报告提出整改建议，不改变已确认的 PRD，不自动为账号扩大权限。审查期间未修改产品源码、业务数据或 `test` 的权限。

## 1. 优先级与验证方式

- **P1**：可能误操作其他任务，优先修复。
- **P2**：正常路径无法完成、数据输入丢失、反馈与结果不一致，或已要求的功能不可达。
- **设计缺口**：现有行为可能符合接口契约，但用户难以理解或完成目标，需要补充交互设计。

工程、前端和浅绿工作台技能及仓库契约作为审查基线。三个并行审查分别覆盖成员/引导、协作/资产、开发/会话，主审交叉核对源码并运行隔离浏览器探针。

隔离探针使用实际 `web/dist` 构建、项目假数据、模拟 API 和 EventSource，在 Edge 中复现了 7 条交互异常；浏览器 JavaScript 错误为 0。探针拦截全部页面请求，不连接真实业务服务，不执行 Git、Codex 或 TAPD。

本机证据位于忽略目录 `state/ux-review/`：`probe.cjs`、`results.json`、`empty-project-workspace.png`、`wrong-session-fallback.png`。这些是本次审查证据，不是已纳入 CI 的回归测试。

## 2. 确认的问题

### F01 · P1 · 指定会话不存在时，自动打开另一条会话

**触发与结果：** 开发空间存在任务 A，用户从项目任务 B 点击“打开我的会话”；B 的 run 尚未形成或已归档，不在普通列表中。初始化找不到 B 后直接选择列表第一条 A，URL 仍携带 B 的 key。用户可能把补充指令发送到 A。

**依据：** [use-workspace-console.js](../../web/src/app/use-workspace-console.js) 第 148–150 行；[ProjectTasks.vue](../../web/src/features/projects/ProjectTasks.vue) 第 20 行。项目任务在执行前已有 runKey，因此失败/待确认启动也能进入这条路径。隔离浏览器确认 URL 指向 `missing-task-b` 时打开了 `1-1`。

**整改：** 有明确 task key 时只读取该任务，按结果显示不存在、已归档、准备中或启动待确认；未指定任务才允许默认选择。失败页可以提供返回任务列表，不能静默替换对象。

### F02 · P2 · 会话“刷新”删除未发送文字和图片

**触发与结果：** 在会话输入草稿或添加图片，点击标题栏“刷新”。按钮调用 `open(active)`，它先执行打开回调，再请求详情；回调清空文字与图片，即使请求失败也无法恢复。

**依据：** [WorkspaceConsole.vue](../../web/src/app/WorkspaceConsole.vue) 第 111–116、355–357 行；[use-session.js](../../web/src/features/session/use-session.js) 第 92–103 行。文字丢失已在浏览器复现，图片清理由同一回调确证。

**整改：** 同一会话刷新使用已有 `refreshSession`，保留草稿、附件及阅读上下文。真正切换任务的草稿策略应单独定义。

### F03 · P2 · 点击评论/交付标签删除草稿

**触发与结果：** 输入评论，点击“变更历史”再回来，甚至重复点击当前“评论”，正文立即清空。提交期间切换标签并输入新正文，旧请求成功回调也会清空新正文。

**依据：** [IssueDiscussion.vue](../../web/src/features/projects/IssueDiscussion.vue) 第 13–14 行；原 SFC 响应式探针及浏览器点击当前标签均复现。

**整改：** 评论和交付分别保存草稿；当前标签重复点击不改变输入；提交只清理该次请求提交的草稿，不清理后来输入的内容。

### F04 · P2 · 编辑冲突后按提示刷新，仍然无法保存

**触发与结果：** 两人编辑同一项目设置或事项，另一人先保存。当前用户保存收到 409 后，点击“刷新项目”或“刷新详情”，再次保存仍携带旧 revision，再次失败。刷新更新了展示数据，却没有更新编辑基线。

**依据：** [ProjectSettings.vue](../../web/src/features/projects/ProjectSettings.vue) 第 10–15 行；[ProjectOverview.vue](../../web/src/features/projects/ProjectOverview.vue) 第 12、25 行；[IssueDetail.vue](../../web/src/features/projects/IssueDetail.vue) 第 19–24、30 行。浏览器确认服务端已返回 revision 2，项目表单仍提交 1；事项路径经原 SFC 探针确认。

**整改：** 提供“保留草稿，加载最新内容”及合并/放弃选项。只有用户解决冲突后才更新编辑基线；不能只替换 revision 后覆盖他人的修改。后台轮询也不能默默覆盖正在编辑的表单。

### F05 · P2 · “刷新任务”不刷新正在查看的任务详情

**触发与结果：** 打开开发任务详情，任务执行状态或追加资料状态已变化，点击“刷新任务”。只请求列表并更新 `data.tasks`，页面继续展示旧的 `selected`，需退出详情再打开才能看到最新状态。

**依据：** [ProjectTasks.vue](../../web/src/features/projects/ProjectTasks.vue) 第 11、14、19–20 行。浏览器确认刷新未请求选中任务详情，详情文本未变化。

**整改：** 选中任务时刷新对应详情；列表与详情分别处理请求状态，保留搜索和待追加事项选择。

### F06 · P2 · 空开发空间进入旧的个人工作区设置

**触发与结果：** 项目成员准备好仓库但尚无任务，点击“打开开发工作台”；或归档最后一条可见会话。空列表直接打开旧 `SettingsPanel`，显示重命名、基准引用、TAPD 和提示词设置。项目模式中的这些入口不适用，重命名事件没有对应父级处理，受限设置请求由后端拒绝。

**依据：** [WorkspaceConsole.vue](../../web/src/app/WorkspaceConsole.vue) 第 125–127、307 行；[WorkbenchApp.vue](../../web/src/app/WorkbenchApp.vue) 第 42 行。浏览器复现并留存截图。

**整改：** 空项目空间显示“尚无开发任务”，提供直接选择项目事项的入口。项目公共设置统一从项目设置进入并受权限控制。此项是错误页面与不可用操作，未确证越权写入。

### F07 · P2 · 成员添加成功，但对方仍看不到项目

**触发与结果：** 在“添加成员”仅选择用户并保存，默认权限为空。后端接受 active 成员关系；负责人看到“参与中 · 0 项有效权限”，成员项目列表却没有此项目。

**依据：** [ProjectMembers.vue](../../web/src/features/projects/ProjectMembers.vue) 第 10、23 行；[project-services.cjs](../../src/application/project-services.cjs) 第 94 行；域校验接受空权限数组。

**整改：** 将“参与中”与最低项目可见权限统一：添加时明确包含 `project.view`，若部门上限不允许则阻止保存并解释原因。若产品要保留零权限关系，应呈现为明确的待授权状态，不能表达为已可参与。

### F08 · P2 · 创建项目入口与实际资格判断不一致

**触发与结果：** 系统管理员归属的有效部门没有 `project.configure` 或 `project.members.manage`。列表返回可以创建，管理员填写表单后，后端校验初始负责人权限超出其部门上限，创建失败。

**依据：** [project-permissions.cjs](../../src/domain/project-permissions.cjs) 第 63–65 行；[project-services.cjs](../../src/application/project-services.cjs) 第 97、132 行。域探针确认管理员资格返回 true，但初始权限校验失败。

**整改：** 创建入口、前置检查与实际创建共用一套资格判断；在填写前说明缺少的条件和配置入口。保留“系统管理身份不自动获得项目所有权限”的边界。

### F09 · P2 · 已移除成员仍能被选择新增，但新增必然失败

**触发与结果：** 移除成员后，通过“添加成员”再次选择同一用户。候选列表包含该人，但新增接口因为历史关系存在而返回 409。用户必须自行猜到进入历史行“调整权限”再修改成员状态。

**依据：** [ProjectMembers.vue](../../web/src/features/projects/ProjectMembers.vue) 第 16–17、23 行；[project-store.cjs](../../src/storage/project-store.cjs) 第 44 行。

**整改：** 活跃成员不出现在新增候选中；已移除成员提供明确的“恢复成员”操作，复用原关系和空间身份。

### F10 · P2 · 清空 TAPD 项目 ID 后，“清除 Cookie”显示成功但未执行

**触发与结果：** 已有 TAPD 配置，删除项目 ID，勾选“清除已保存 Cookie”并保存。前端因为 ID 为空，不提交整个 `tapd` 字段；后端保留旧配置。页面仍显示保存成功并取消清除勾选。

**依据：** [ProjectSettings.vue](../../web/src/features/projects/ProjectSettings.vue) 第 14–15 行；[project-services.cjs](../../src/application/project-services.cjs) 第 105–123 行。原 SFC 探针确认请求未包含清除意图。

**整改：** 独立表达清除凭据与解绑项目的操作；或者明确校验并阻止无效提交，不能忽略用户选中的清除操作。

### F11 · P2 · 资产修订历史超过一页后不可达

**触发与结果：** 资产超过 30 次修订，打开“修订历史”。请求没有 offset，页面不处理 `history.nextOffset`，只能看到第一页，早期记录无法通过界面访问。

**依据：** [ProjectAssets.vue](../../web/src/features/projects/ProjectAssets.vue) 第 34、39 行；[project-content-store.cjs](../../src/storage/project-content-store.cjs) 的 `assetHistory` 返回分页信息。

**整改：** 历史使用独立分页状态及加载更多/翻页入口，切换资产时重置。

### F12 · P2 · 事项、任务、资产详情没有可恢复的页面地址

**触发与结果：** 从列表打开详情，地址仍是项目页与 tab。刷新会回到列表，复制地址无法让其他成员定位同一对象，浏览器后退也无法准确回到本次打开详情前的位置。

**依据：** [router.js](../../web/src/app/router.js) 只定义项目根路径；[ProjectIssues.vue](../../web/src/features/projects/ProjectIssues.vue) 第 11、24 行、[ProjectTasks.vue](../../web/src/features/projects/ProjectTasks.vue) 第 9、14 行、[ProjectAssets.vue](../../web/src/features/projects/ProjectAssets.vue) 第 11、24 行仅在局部状态保存选中对象。事项详情刷新回列表已在浏览器复现；任务与资产为代码路径确证。

**整改：** 为事项、开发任务、资产建立含对象 ID 的详情路由或查询参数；刷新、分享、前进/后退均恢复相同对象，返回列表保留筛选与页码。

## 3. 流程和信息设计缺口

### D01 · 初始化及创建项目后的下一步缺失

首次管理员未配置部门时，“我的项目”也显示“项目负责人添加你为成员后，项目会显示在这里”。没有引导其完成部门、本人归属和仓库登记。

创建项目后直接进入概览；创建者只有 `project.view`、`project.configure`、`project.members.manage`，需求和开发入口按权限隐藏。最小授权本身符合现有规则，但没有后续配置引导。

`test` 的实际情况正属于后一类：部门上限允许开发，但项目成员只获三项管理权限，尚未分配开发空间；有个人 Git 账号也不能替代项目授权。根因不是 Codex 菜单随机丢失。

依据：[ProjectDirectory.vue](../../web/src/features/projects/ProjectDirectory.vue) 第 15、24、29 行；[ProjectOverview.vue](../../web/src/features/projects/ProjectOverview.vue) 第 15 行；[project-services.cjs](../../src/application/project-services.cjs) 第 132 行。

建议：管理员显示初始化清单；新项目显示“配置成员及本人权限”的主操作，并展示当前账号的有效权限与受限原因。不能通过给创建者默认全权掩盖这个问题。

### D02 · 日常开发入口分散，阅读需求后无法顺势开始开发

阅读事项详情后，用户必须返回列表勾选事项才能启动开发；开发任务藏在“开发空间”的账号/仓库准备内容下。开发工作台的“从项目事项启动开发”又只返回项目概览，需要继续寻找需求/Bug。

依据：[ProjectIssues.vue](../../web/src/features/projects/ProjectIssues.vue) 第 24、29 行；[IssueDetail.vue](../../web/src/features/projects/IssueDetail.vue) 第 30–39 行；[ProjectDevelopment.vue](../../web/src/features/projects/ProjectDevelopment.vue) 第 18–19 行；[WorkbenchApp.vue](../../web/src/app/WorkbenchApp.vue) 第 42 行。

建议：授权用户在事项详情直接“启动开发”，列表保留多选融合；开发任务成为项目一级入口，个人 Git/空间准备作为首次开发的前置步骤。工作台返回准确的来源事项/任务，空状态直接到事项选择。

### D03 · 权限编辑暴露细项，但缺少面向工作内容的操作

当前逐项勾选权限自动补依赖，后端也有产品/开发模板，但成员页没有使用模板。维护者必须理解代码查看、代码操作、会话查看、启动、续聊和审批之间的关系；只勾“启动”并不代表具备完整开发流程。

依据：[ProjectPermissionEditor.vue](../../web/src/shared/components/ProjectPermissionEditor.vue)；[project-permissions.cjs](../../src/domain/project-permissions.cjs) 中产品/开发模板；[ProjectMembers.vue](../../web/src/features/projects/ProjectMembers.vue)。

建议：增加“产品协作”“仅代码操作”“Codex 开发”等可预览的授权组合，再允许细调；模板是权限集合，不新增强制职位或绕过部门上限。保存前显示成员实际能使用的功能，明确部门未开放项。

### D04 · 资产填写的信息无法在正常阅读页使用

资产可填写关联事项、负责人和有效期，但详情不显示这些信息。已有事项只在编辑中显示关联数量，用户要再次搜索才能找到已关联对象；只读成员无法通过正常详情识别关联对象。

依据：[ProjectAssets.vue](../../web/src/features/projects/ProjectAssets.vue) 第 38–39 行。属于 PRD §8 已要求能力的阅读呈现缺口，建议按 P2 补齐。

建议：显示负责人姓名、有效期和关联事项编号/标题；有事项权限时可跳转，无权限时提供受限提示。编辑时独立列出已关联项，不依赖当前搜索结果。

### D05 · 历史记录把存储结构直接展示给用户

事项和资产历史直接渲染 `JSON.stringify(entry.data)`；字段名、UUID、完整前后快照及原始时间使产品/测试成员难以快速判断“谁改了什么”。

依据：[IssueDiscussion.vue](../../web/src/features/projects/IssueDiscussion.vue) 第 16 行；[ProjectAssets.vue](../../web/src/features/projects/ProjectAssets.vue) 第 39 行。

建议：默认显示“某人将负责人从甲改为乙”“验收状态从待验收改为通过”等可读变化、当地时间和有效链接。技术详情可折叠。作为后续体验完善，不阻塞更高优先级修复。

## 4. 建议统一的使用流程

| 使用者/场景 | 主流程 | 必要的反馈 |
| --- | --- | --- |
| 系统管理员首次配置 | 建立平铺部门及权限上限 → 用户归属 → 登记仓库 → 创建项目 | 显示缺少的配置及直接入口；创建资格与后端一致 |
| 项目负责人 | 创建项目 → 为自己及成员选择权限组合 → 完成配置 | 分清管理权限与开发权限，预览成员实际可用功能 |
| 产品/测试等协作成员 | 我的项目 → 需求/Bug → 详情 → 评论、状态流转、交付与验收 | 只呈现获授权功能，不要求 Git 或出现 Codex 输入区 |
| 仅操作代码的成员 | 项目 → 代码入口 → 必要时准备个人 Git/空间 → 查看或操作仓库 | 不强制拥有或显示 Codex 会话 |
| Codex 开发成员首次开发 | 事项详情“启动开发” → 检查授权、Git 和空间 → 确认并启动 → 对应任务会话 | 准备成功后保留原事项选择；执行不自动改变业务状态 |
| Codex 开发成员日常操作 | 项目开发任务 → 精确任务 → 会话/代码 → 发布项目交付结果 → 人工验收 | 保留来源、草稿和链接；开发结束与验收结果分别呈现 |

项目层建议保留“概览、需求、Bug、资产、成员、设置”，将日常“开发任务”和“代码”按能力开放。个人空间的分配/准备状态可以在首次使用时出现，不应成为所有开发操作必须绕行的页面。仅有代码权限的用户仍有独立入口。

所有对象详情采用稳定地址。页面刷新只更新当前对象的服务端状态，标签切换保留本对象草稿；上下文切换有明确的草稿策略。保存失败保留输入，冲突提供可执行的恢复操作。

## 5. 整改顺序与验收建议

1. **先修错误对象与输入丢失：** F01、F02、F03。失效/归档/未形成 run 的指定任务不打开其他任务；刷新、重复点标签与慢请求完成均不丢草稿。
2. **统一刷新与保存语义：** F04、F05、F10。两个浏览器编辑同一对象能够恢复冲突；详情刷新获取真实最新状态；清除操作结果与提示一致。
3. **打通项目授权与首次开发：** F06–F09、D01–D03。新管理员、新项目、零权限成员、受限部门、仅代码成员、Codex 开发成员分别走通主流程；不以默认全权替代设计。
4. **建立可恢复导航与协作阅读：** F12、F11、D04、D05。详情可分享、刷新和前进/后退；资产关联与历史完整可达。

实现回归需使用隔离 PostgreSQL、临时 Git、fake Codex 与模拟 TAPD，并执行仓库要求的 lint、架构/单元/集成、构建及浏览器检查。UI 改动还需验证 1440、768、390、320px 下的入口、焦点与草稿行为。
