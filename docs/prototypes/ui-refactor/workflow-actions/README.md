# 事项处理与流程编排 · 三方案评审

日期：2026-10-16。阶段：用户已选定 A，正式实现与本地验证已完成。

[打开原型](index.html)。可直接打开本地 HTML；全部使用内存中的模拟数据，不请求业务接口。

## 本轮统一的交互规则

1. 只有存在比事项当前绑定版本更新的**已发布版本**，才显示「采用新流程版本」。正式实现继续检查权限、事项状态及关联任务兼容条件；没有更新版本时隐藏入口。
2. 有其他可用处理动作时，不显示「当前没有可用的状态操作」。当前阶段需要别人处理时，说明下一步和处理人。
3. 单条、批量指派成功后保留当前事项或列表、筛选与阅读位置，刷新负责人及任务信息。用户主动点击「查看开发任务」才进入开发页面。
4. 按用户更正，**「线下处理」沿用现有「已有成果」流程**，复用交付表单、校验、验证人选择、共享确认及送验、退回、重提行为；不增加独立处理流程或额外步骤。正式实现的入口名称读取当前送验连线，「线下处理」仅为推荐模板配置的名称。
5. 推荐模板从待开发节点配置「线下处理」，未到待开发时不配置直接送验。运行时读取绑定流程的连线和权限，不按节点、类别或顺序限制；自定义流程可以配置其他合法节点与名称。
6. 开发列表默认排除 `cancelled`，待开发、开发中、已完成等其他状态仍展示。提供「全部状态」「已取消」筛选，列表、计数和分页采用同一筛选条件。
7. 原「载入推荐流程」整理为「流程模板」：先查看模板和替换范围，再载入草稿，随后沿用保存、发布。原「模拟一次交接」整理为「交接预览」，展示状态变化、必填资料和下一处理人。

「图生图保留图片文字设计并移除额外营销文案」和「视频结果页支持当前页面直接下载视频」仅作为原型样例；正式事项没有被修改。

## 三种方案

| 方案 | 事项处理 | 流程编排 | 适合场景与取舍 |
| --- | --- | --- | --- |
| A · 侧栏办理（推荐） | 右侧显示当前状态、处理人和主操作；同一送验表单在集中弹窗内完成 | 主画布与属性并列；模板、预览按需展开；保存和发布集中在页头 | 日常协作路径清晰，保留完整阅读上下文；窄屏改为上下排列 |
| B · 页内办理 | 内容与同一送验表单在页内切换，长表单有更多空间 | 设计、交接预览、版本发布三个工作区，业务流程不变 | 适合长内容及完整核对；切换工作区次数较多 |
| C · 抽屉办理 | 事项列表与详情同屏；同一送验表单放在侧边抽屉 | 版本目录、画布、属性并列；可在侧边预览交接 | 适合连续处理多个事项；桌面信息密度较高 |

三套采用仓库中性视觉变量：白色、浅灰、石墨按钮，紫色仅用于当前选择和少量强调。方案差异是信息组织和表单位置，不是三套业务流程。

## 可体验内容

- 顶部切换 A/B/C，再切换「事项处理」「开发列表」「流程编排」。
- 演示场景包含待开发、已指派、待评审、已使用最新流程版本。
- 指派后观察页面保持原位、负责人更新；线下处理填写成果、验证人及共享确认后进入待验证。
- 采用新版本后入口消失；开发默认隐藏取消任务，可显式筛选查看。
- 模板载入只修改草稿；交接预览可更换状态和操作；发布需核对影响范围。
- 中文为主要评审语言；EN 可检查主要控件的英文长度和响应式布局。业务正文和自定义状态示例保留原文。
- 表单使用模拟结果，不触发真实开发、交付或流程发布。

## 选定后的实施范围

事项详情、讨论交付入口、开发任务中的同类入口统一命名；修正各入口指派后的导航；为版本入口提供最新已发布版本依据；开发列表筛选需覆盖查询、计数及分页；重构系统流程工具和对应中英文文案。

A 已完成正式 Vue 与后端实施，并按后续授权部署到现有 Linux 服务。操作名称、可用节点、目标和交接规则均从流程配置读取；「线下处理」是推荐模板连线名称，不是程序固定分支。未执行数据库迁移或修改已发布流程。ESLint、663 项架构/单元/集成测试、构建及九组浏览器脚本已通过，本地完整验证平台为 Windows / Edge，部署机另完成 Linux 构建与服务检查；详情见[流程按钮审查记录](../../../reviews/workflow-actions-a-2026-10-16.md)。
