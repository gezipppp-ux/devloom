# 合并开发任务 · 间距修正三方案

日期：2026-10-26。阶段：用户已选定「舒展分区」，正式 Vue 实现及本机回归已完成。

[打开三套方案](index.html)。使用底部方案切换器浏览；输入、清单展开、取消和确认均为本地模拟，不访问生产接口。

## 问题定位

原 `MergeDevelopmentDialog.vue` 复用 `workspace-dialog` 和 `project-form`。`style.css` 中弹窗标签选择器包含两个 `:not()`，优先级高于 `projects.css` 中表单标签规则，将 `display:flex` 覆盖为 `display:block`；标签与输入框的 `gap:8px` 因而失效。列表使用默认 `ul/li`，条目没有独立间距。表单 gap、段落默认 margin、底部 actions 的 margin/padding 叠加，导致部分区域拥挤、部分区域过空。

## 共同调整

- 当前任务是核对合并范围并命名，唯一主操作是「确认合并」。右上角仅保留关闭，底部取消在左、确认在右。
- 标签和输入框分成独立布局行，默认间距 12px；内容分区 28px；底部按钮间距 12px，正文不叠加浏览器默认段落 margin。
- 长标题使用可换行编辑区并显示 200 字上限。任务列表以轻分隔线、序号和独立元信息组织。
- 保留原任务合并记录、事项独立跟踪、合并后仍需手动启动开发的边界。
- 使用仓库中性视觉变量对应的白色、浅灰、石墨与紫色。原型样式独立于生产 CSS。
- 桌面限制弹窗行宽；窄屏左右分栏变为上下排列，按钮触控目标至少 44px。预览内容随高度自然增长，页面滚动可到达全部表单和操作。

## 三种方案

| 方案 | 组织方式 | 取舍 |
| --- | --- | --- |
| 舒展分区（推荐） | 完整任务清单 → 标题 → 合并影响 → 操作 | 接近原操作顺序；全部来源可直接核对，长清单需要更多纵向空间 |
| 标题优先 | 标题 → 可展开任务清单 → 合并影响 → 操作 | 默认更紧凑；完整核对多一次展开 |
| 左右对照 | 左侧原任务，右侧合并后的标题与影响，底部统一操作 | 桌面便于对照；手机单列后高度接近舒展分区 |

宿主调整面板支持标签间距、分区间距、中文/英文、正常/多任务/空选择/失败/只读；每套标题草稿独立保留。用户切换方案只是浏览，不表示确认选型。

- 功能：标题空白禁用、字数更新、清单展开、模拟确认、取消/Escape、焦点限制与返回、失败后保留草稿、只读与空选择、多任务及语言切换保留草稿。
- 视觉：Windows / Edge 检查三套布局 × 中英文 × 1920×1080、2560×1440、1440×900、1280×720、768×1024、390×844、320×740，共 42 组真实 CSS 视口；查看完整页面截图和中英文汇总图，补查聚焦输入框、展开清单及 12 项任务。未发现横向溢出或标签与焦点框重叠。
- 输入框焦点边框与标签保留空间；手机英文主按钮保持单行。正常示例保持实际截图中的长中文标题，不用短占位内容规避布局问题。
- 浏览器脚本异常和原型外部请求均为 0；预览确认不会合并真实开发任务或启动 Agent。
- 原型截图与校验记录保存在忽略目录 `state/browser/merge-development/`。原型阶段仅新增设计资料，原型验收与下述生产实现验收分别记录。

`preview.html` 是可维护的会话预览源；`index.html` 是包含独立预览运行时的生成版本。原型继续保留三种方案供设计追溯。

## 正式实现

`MergeDevelopmentDialog.vue` 复用共享 `ModalDialog`，沿用「任务清单 → 标题 → 影响说明 → 操作」顺序，桌面宽度 624px，标签间距 12px，正文分区 28px。页头和底栏保持可达，短屏与多任务只滚动正文；宽度与页头样式显式限定到此弹窗，避免共享弹窗规则覆盖。标题使用多行编辑区并显示字数，页头数量使用国际化命名插值及本地化数字。

保留原合并接口、稳定 requestId、任务 revision、保存中禁止关闭和失败草稿。全局开发列表与项目列表共用该组件；合并仍不执行 Agent。新增 `test/browser/merge-development-dialog.test.cjs` 由既有 `development-flows.test.cjs` 调用，覆盖布局、焦点返回、中英文草稿、空白校验、保存中禁用、冲突重试身份及 20 项任务短屏滚动。
