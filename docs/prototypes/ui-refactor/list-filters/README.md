## 已确认范围

- 事项列表显示提报人，筛选版本、事项状态、优先级、开发负责人、提报人。
- 开发列表显示来源事项提报人，筛选任务状态、版本、执行者、提报人。合并任务按当前来源事项去重显示多人；独立开发显示“无关联事项”。默认未取消，可显式查看全部状态或已取消。
- 交付列表显示版本和提报人，新增这两个筛选，保留验收状态与提交人。
- 不同维度取交集，同一维度多选取并集；候选值不取当前页，查询、计数及分页使用同一条件。
- 保留事项、任务、Agent 状态的边界；筛选不扩大原访问范围，全局开发仍为本人任务。项目全部任务沿用原项目权限入口。
- 正式核对模型后，交付的提报人来自本次交付关联的具体事项，不能汇总该任务其他事项的提报人；独立交付无来源事项。版本优先来自该事项，独立任务交付读取任务版本。

## 实施设计

正式实现复用 `ListFilters` 与既有 `AppSelect`。通用组件只呈现字段配置、选择及重置；功能层提供字段、候选值和 URL 查询。桌面常驻，手机以筛选按钮打开统一模态表单，选项变更生效并保留当前表单，点击查看结果返回列表。

全局及项目事项、开发队列复用相同组件。后端按授权范围返回完整候选元数据，筛选在数据库分页前执行；全局开发的候选限定为本人全部任务涉及的版本和人员，不读取其他任务或事项流程。版本与人员 ID 作为筛选身份，事项状态来自已绑定及最新发布的流程版本，不使用固定中文名称或未发布草稿。

图片问题定位：开发详情的 `MarkdownContent` 缺少 `images` 映射，安全渲染器因此移除 `src`。修复在应用 presenter 返回经过项目、事项、文件签名与快照哈希核对的图片映射；开发详情传入该映射。已有执行快照、来源身份、工作树与会话保持不变，不允许任意远程图片绕过白名单。
