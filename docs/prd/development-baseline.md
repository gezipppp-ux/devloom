# 开发分支与远端更新

## 目标

开发任务明确记录从哪个远端分支开展工作。每次新建任务工作树前获取所选分支的最新提交，以固定提交创建独立任务分支，避免从当前检出目录或过期引用开始开发。

## 基线规则

- 项目和事项不保存默认或建议分支。
- 开发执行人必须在任务开始前从实时远端分支列表选择本次分支，不接受 HEAD、标签、提交 SHA 或完整引用表达式。
- 开发任务受理时保存不可变 `snapshot.baseBranch`。同一请求重试复用原快照；更换分支不能复用原请求标识。后续修改项目或事项不改变已受理任务。

## 创建与继续

1. 按原权限验证事项、个人开发空间、Git 账号和启动能力，保存任务受理意图。
2. 保存运行准备状态。在共享 Git 目录的操作锁中检查 origin 地址与空间绑定地址，使用该成员的 Git 账号获取 `refs/heads/<branch>`。
3. 获取成功后解析提交 SHA，记录 `worktree.baseline = { remote, branch, commit, fetchedAt }`，以该 SHA 生成并保存 worktree 计划。
4. 再次授权后创建独立分支和工作树，执行初始化命令，然后启动 CLI Agent。不会 pull、checkout、reset 或覆盖源仓库未提交内容。
5. 网络失败、分支不存在、权限撤销或取消均停止。失败记录在刷新后仍可见，不使用旧的 tracking ref，不自动重试或重复启动。

已有任务续聊与重载保持原提交、工作树路径及会话身份，不自动 fetch/rebase。向已有任务追加事项不重新选择基线；保存和发送追加资料都不会重新创建工作树。

任务列表和详情展示分支、实际提交与获取时间。获取尚未成功时不得把本地旧 SHA 显示为本次基线。其他成员只能按既有项目权限查看基线元数据，个人会话内容和 Git 凭据继续隔离。

## 不包含

分支合并、自动推送、发布管理、跨仓库任务、自动升级已有任务基线，以及旧 `baseRef` 配置兼容。业务工作树、会话和来源身份不迁移、不删除。

## 验收

- 克隆后远端新提交、未检出的非默认分支、force push 都以本次获取的准确提交开始。
- 分支删除、网络失败、origin 地址变化、取消和权限撤销不创建工作树、不启动 Agent。
- 多请求共享仓库时，获取、固定 SHA、保存计划和创建使用同一 Git 操作锁；占用时明确提示重试。
- 任务分支选择、请求幂等和历史快照可通过隔离数据库回归。
- 失败状态可持久读取；已有运行不重复获取或执行。桌面与窄屏均能看到确认分支和底部操作。

验证只使用临时 bare remote、隔离 PostgreSQL 与 fake Agent，不执行真实需求或写入 TAPD。
