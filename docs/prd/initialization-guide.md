# 首次初始化引导方案

状态：方案和交互原型已确认，正式实现与本地验证完成。
更新：2026-10-13。根据最新需求，**管理员也在向导内创建；取消用户首次登录冒泡引导**。

## 目标与范围

首次部署通过连续步骤创建管理员，并完成服务环境、成员目录和团队配置，支持保存后继续；测试账号和第一个项目可以分别跳过。

流程：**创建管理员 → 环境检测与安装 → 成员项目与任务目录 → 部门与权限 → 测试账号（可跳过）→ 第一个项目（可跳过）→ 完成**。

提供[可交互原型](../prototypes/initialization-guide.html)。原型只使用浏览器内的演示数据，不连接业务 API，不安装软件，不创建真实目录、部门、账号或项目。工具版本、路径和项目均为示例。原型的“评审场景”允许直接查看异常状态及后续页面；正式产品没有该工具栏。

实现入口为 `/setup`，新增迁移 `20261013150000_initialization_guide`，运维凭证命令为 `npm run setup:link`。本地已完成 lint、后端回归、构建、Jenkinsfile 中的浏览器回归及新增初始化端到端测试；使用隔离 PostgreSQL、模拟环境探针/安装器，未执行真实需求或修改生产配置。实际 Vue 截图见运行后生成的 `state/browser/setup/index.html`，覆盖 1440、768、390、320px。当前实机验证平台为 Windows + Chrome，Linux 与真实安装器依赖 CI/目标主机验证。

## 入口与触发

- Node.js 22.13+、npm、PostgreSQL 和数据库部署仍通过现有安装流程准备。这些是 Web 服务能启动的前提；无需先执行 `npm run init:admin`，管理员在网页向导内创建。
- 全新部署没有账号时，服务启动终端输出有效期 30 分钟的一次性初始化链接。打开 `/setup#token=<一次性凭证>` 进入管理员创建页；浏览器读取后立即移除 fragment，凭证只留内存。直接访问页面可粘贴终端提供的初始化凭证。链接用于确认首次配置者持有服务器访问权。
- 凭证由服务端安全随机生成，只保存摘要和有效期；创建管理员时事务内消费。失效后由服务器运维入口重新签发；重启尚未初始化的服务可轮换凭证。不得通过公开 HTTP 无认证重置凭证。
- 管理员创建成功后建立正式登录会话并继续向导，不需要重复登录或首次改密，因为密码由本人设置。后续登录仍按既有认证机制处理。
- 保留 `npm run init:admin` 作为运维入口；如果已通过命令创建管理员，则管理员登录后从环境检测继续。不会重复要求创建或修改已有管理员。
- 引导状态独立持久化，不能每次根据“项目数量为零”重新触发。删除项目、账号或清空浏览器数据不重置部署状态。
- 新增迁移时一次性分类：完全空部署标记为 `awaiting_admin`；尚无业务记录、只有初始管理员的部署标记为 `pending` 并记录管理员步骤已完成；已有部门、普通成员、项目、工作区或运行记录的当前基线部署标记为 `not_required`，不自动补建或覆盖团队。只有 `awaiting_admin` 且从未完成管理员创建的空部署才能接受一次性凭证；以后停用/删除账号不重新打开创建入口。
- 初始化未完成时，管理员登录继续上次已保存步骤；普通成员只看到“管理员正在完成初始化”。引导及相关环境/目录操作以外的业务写入暂不可用，认证与退出始终可用。
- “保存并退出”保存非敏感草稿和已完成步骤，退出到登录页；管理员尚未创建时回到初始化入口，再次进入仍需有效凭证。密码不保存为草稿。安装已开始时退出页面不取消安装。
- 完成后进入“全部项目”或刚创建的项目。系统设置提供只读“初始化记录”和未完成时的“继续初始化”；不提供一键重跑已完成创建动作。

## 页面与行为

| 步骤 | 页面内容 | 继续条件 / 跳过规则 |
| --- | --- | --- |
| 1 创建管理员 | 登录名、显示名称、密码、确认密码 | 入口凭证有效、输入校验通过，原子创建初始管理员；不可跳过 |
| 2 环境检测 | 服务端 Node/npm/PostgreSQL 概况、Git/Codex 检测、安装来源与版本、安装状态、Codex 登录状态 | Git/Codex 工具检测通过；Codex 登录可明确选择稍后处理 |
| 3 目录配置 | 共同基础目录、浏览服务器目录、项目及任务路径预览、创建与可写校验 | 路径合法且保存校验通过；必填 |
| 4 部门与权限 | 产品部门、研发部门和各自的默认权限，展开查看细项 | 系统创建成功后继续；不可跳过 |
| 5 测试账号 | 默认选中两个账号，可单独取消；显示名、登录名、初始密码、部门 | 至少选择一个并通过创建校验，或跳过全部 |
| 6 第一个项目 | 项目名称、Git 地址、可选说明、负责人、测试成员及授权 | 合法输入并创建成功，或跳过 |
| 7 完成 | 管理员、目录、部门、账号、项目及待办汇总 | 标记完成，进入项目或全部项目 |

### 创建管理员

- 登录名建议 `admin`，允许按现有账号规则修改；显示名称默认“管理员”。密码及确认密码为空，沿用 6–256 字符规则。
- 第一个账号固定为系统管理员，角色由服务器决定，不接受客户端提权参数；不要求所属部门。
- 初始密码由本人设置，`mustChangePassword=false`；可选测试账号仍保持首次改密要求。
- 一次性凭证、空部署条件、账号唯一性和初始化修订号在同一事务内校验，创建账号、记录管理员身份并消费凭证一并提交。两个标签页同时提交只能创建一个初始管理员。
- 成功后轮换 session ID 并建立登录；如果账号已创建但登录响应丢失，页面提示使用刚创建的账号登录继续，不重复创建管理员。
- 无凭证/过期时展示“请从服务终端重新获取初始化链接”，不透露服务器路径、工具版本或任何业务数据。登录名和显示名可保留非敏感草稿，密码不持久化。

### 环境检测与安装

1. 自动检测服务所在机器，正常版本保留；不将“有新版本”视为不满足要求。
2. 缺失 Git/Codex 时展示安装目标和来源，由管理员点击一次“安装缺失工具”，顺序执行受支持的安装。先 Git 后 Codex，每项结束后实际复检；使用阶段文案，不虚构整体百分比。
3. 复用 `EnvironmentServices` 的工具白名单、确切版本、安装器检测、管理员复核与任务互斥。Windows Git 使用 winget，Linux Git 使用 APT/DNF；Codex 使用已支持的 npm 安装路径。不能自动安装时说明原因，提供“已在服务器处理，重新检测”。不接受自定义命令或下载源。
4. 只有明确缺失才自动安装；启动失败、版本解析异常、错误 `CODEX_BIN` 或已有安装但 PATH 不可见均先报告异常，避免重复安装。确有不兼容版本时展示修复项，沿用既有更新能力或由运维修复，不强行覆盖未知安装。
5. 安装失败保留已成功项，显式重试只处理仍缺失的工具。目标版本变化时重新展示安装计划；服务重启后重新检测，不根据旧进度重放安装。
6. 安装后尚需刷新 PATH 时显示“已安装，待重启”，该项不算通过；重新检测确认后才能继续。网页不自动重启服务或提权。
7. Codex CLI 已安装但未登录时单独显示“待认证”，提示在实际服务账号下完成现有登录流程并重新检测。可选择“稍后登录，继续配置”，完成页保留待办；真正启动开发仍检查引擎认证。账号/项目创建不依赖这项认证。
8. Node/npm/PostgreSQL 的启动前检查保留现有 CLI 报错；网页中的数据库状态是已连接和迁移校验结果，不表示网页能够安装或修复数据库。

### 成员项目与任务目录

- 延用唯一系统设置 `memberStorageRoot`，项目克隆与任务 Worktree 共用基础目录，不引入第二份路径配置。
- 默认带入当前配置，给出 Windows `D:\wt` / Linux `/srv/wt` 示例；明确这是服务器路径。
- 点击“保存并继续”时创建缺失目录并做真实写入探测；路径错误、文件占用或无权限时保留输入并展示字段错误。
- 预览按现行账号/数据库契约：`<基础目录>/projects/<仓库目录名>/members/<用户名>/repository-<准备修订号>`；任务为同一成员根下 `worktree/<任务目录>`。
- 路径中使用 Git 仓库名（去掉 `.git`）与登录用户名，例如 `projects/web-coding/members/admin`。同名仓库忽略大小写判重，后创建项目自动加短后缀并保存；显示名称修改不影响目录。新规则不兼容历史数据，不迁移旧 UUID 目录。以后修改基础目录不搬移已记录仓库、任务、会话或 source。
- 现有 `MemberStorageSettings.vue` 的说明仍使用旧用户名路径，实施时同步修正文案，避免两个入口给出冲突示例。

### 默认部门与权限

直接复用 `src/domain/project-permissions.cjs` 的 `productTemplate` 与 `developerTemplate`，不在页面另写一套授权规则。部门按稳定种子键记录创建结果，名称分别为“产品部门”“研发部门”。引导内展示固定默认方案；初始化后管理员可在部门页调整。

| 能力 | 产品部门 | 研发部门 |
| --- | --- | --- |
| 查看项目、需求与 Bug | 有 | 有 |
| 创建、编辑、分派事项 | 有 | 无 |
| 变更事项状态 | 有 | 有 |
| 验收需求、验证 Bug | 有 | 无 |
| 管理发布版本 | 有 | 无 |
| 查看协作、评论、发布交付 | 有 | 有 |
| 查看普通资产 | 有 | 无 |
| 代码查看和仓库操作 | 无 | 有 |
| Agent 会话查看、启动、续聊、审批、停止 | 无 | 有 |
| 项目创建、配置、成员管理、归档 | 无 | 无 |
| 敏感资产字段 | 无 | 无 |

权限来自现有模板的含义：产品负责需求和验收，研发负责代码和执行。系统管理员保持现有管理权限；初始化不会给测试用户系统管理员身份，也不会自动为管理员增加代码/Agent 权限。

部门只定义功能上限。用户必须被加入具体项目并获得项目权限，才可访问对应项目。重试根据初始化记录复用本次创建的部门；发现其他来源的同名部门时报告冲突并要求处理，不静默接管或扩大权限。

### 测试账号（可跳过）

| 显示名 | 建议登录名 | 部门 | 系统角色 |
| --- | --- | --- | --- |
| 测试#产品 | `test-product` | 产品部门 | member |
| 测试#研发 | `test-dev` | 研发部门 | member |

- 登录名遵循现有 3–64 位字母、数字、点、短横线、下划线规则；中文和 `#` 放在显示名里。
- 初始密码由管理员分别填写，沿用现有 6–256 字符校验；没有固定默认密码，不保存浏览器草稿、不写入日志或初始化摘要。首次登录仍强制改密，这是既有安全行为，不是新增引导功能。
- 两个账号可单独勾选；“跳过测试账号”跳过本步全部账号。无选择时引导使用跳过按钮。
- 创建所选账号及记录步骤结果在同一短事务中提交，避免一半成功；登录名占用时保留表单，允许改名或跳过，不覆盖同名现有账号。
- 创建账号仅分配部门，不自动加入所有项目，也不授予创建项目资格。

### 第一个项目（可跳过）

- 必填项目名称、无嵌入凭据的 Git 仓库地址；说明可选。实际表单为空，不预填可提交的演示仓库。
- 当前管理员为项目负责人。显示本次已创建测试账号，默认勾选加入项目；可以取消各成员。
- 产品成员获得上述产品权限，研发成员获得上述研发权限；提交时再次校验当前部门上限，不能超过最新上限。
- 项目、负责人关系、所选成员授权及初始化结果同一短事务落库；复用现有项目创建的业务规则、提示词默认值、开发空间分配规则和审计逻辑。
- 本步骤只创建项目及成员关系。开发成员后续自行绑定个人 Git 凭据、准备仓库并显式开始任务。
- 跳过项目仍可完成初始化；账号保留但没有项目访问权。完成页提示管理员之后创建项目并添加成员。

## 状态、权限与失败恢复（实施设计）

- 增加部署级初始化记录，包含 `version / status / currentStep / revision / steps / initialAdminId / completedAt / completedBy`；另保存初始化凭证摘要/有效期/已消费状态。步骤保存 `pending / completed / skipped`、创建资源 ID 与必要非敏感草稿；环境实时状态单独检测。
- 使用当前 PostgreSQL 基线后的新增版本化迁移，不修改已发布迁移。已有部署的分类只执行一次；不兼容历史旧模型、不回退 JSON 存储。
- 写入携带步骤修订号和 UUID `requestId`。同请求同输入返回原结果，变更输入返回冲突；数据库唯一约束与条件更新防止双管理员/双标签页重复创建。
- 只有初始管理员创建入口接受一次性凭证；匿名状态接口仅返回是否需要创建初始管理员。其他步骤及服务器路径只向有效管理员开放；前端路由守卫只负责体验，后端每一步重新鉴权。安装/目录探测等异步返回后再次授权。首次创建入口保留 Host/Origin、会话 CSRF、限流和正文日志脱敏，不能成为普通账号创建或重置入口。
- 文件探测、软件安装、网络查询与 Codex 认证检查不放在数据库事务中。文件系统成功但状态提交失败时，重试只复检并记录；不删除已经创建的目录。
- 已完成步骤重进时只读展示及复检，不因“返回上一步”重建资源。可选步骤跳过后可在完成前返回填写；初始化完成后从正常账号/项目管理入口新增。
- 响应丢失先读取步骤结果；跨进程安装互斥沿用既有环境能力边界。当前进程内安装状态重启后失效，引导不得把它当作持久安装凭据。
- 完成接口复核必填步骤与实际资源。Codex 认证可留待办；安装失败、待重启、目录未保存、部门缺失不得伪装为初始化成功。

| 层 | 拟调整内容 |
| --- | --- |
| domain | `setup-state.cjs`：步骤顺序、允许的跳过、完成条件和纯输入规则；权限引用现有模板 |
| storage / Prisma | `setup-store.cjs`、部署初始化模型与版本化迁移；幂等记录、事务和修订；复用账号/项目存储规则 |

| HTTP | `setup-api.cjs` 提供最小 `/api/setup/status` 和凭证保护的 `/api/setup/admin`；管理员 `/api/system/setup` 状态、步骤提交、完成；环境安装继续走原接口；增加初始化写门禁 |
| Vue | `features/setup/` 拥有向导表单和生命周期；app 组合 `/setup` 路由、入口和跨功能能力；不得跨 feature 导入业务实现 |
| 文档与架构 | 更新安装步骤、账号数据库契约、前端目录和架构检查中的精确合法目录 |

实施顺序：①持久状态、一次性凭证与管理员创建 → ②其他必填步骤及幂等创建 → ③可选账号/项目 → ④Vue 向导、继续入口与异常状态 → ⑤回归、视觉验证和文档。

## 验收清单

- 空部署通过有效链接创建管理员并自动登录；凭证过期/重放/并发/无凭证创建被拒绝；角色不可由输入决定；完成后不会重新开放初始管理员入口。
- 已有管理员直接登录继续；已有业务的部署不强制进入；匿名及普通成员不能操作后续初始化。
- Git/Codex 缺失可安装；已有合格版本不更新；查询异常、安装失败、无安装器、目标变化、待重启和认证待办都有真实状态。
- 目录校验失败不能继续；Windows/Linux 路径预览正确；历史 worktree 和会话路径保持不变。
- 重复点击、刷新、返回、断线、多管理员并发均不重复创建部门、用户和项目；同名冲突不覆盖已有资源。
- 产品/研发权限与模板一致；跳过账号后不创建账号；跳过项目后用户没有项目权限；加入首个项目时应用相应授权。
- 密码无默认值、不进草稿或摘要；本人创建的初始管理员无需再次改密，管理员代建的测试账号仍需首次改密。
- 退出/刷新后从已保存状态继续，保存失败保留当前输入；安装中的页面离开不触发第二次安装。
