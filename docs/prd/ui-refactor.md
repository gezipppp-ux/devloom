## 目标与已确认决定

采用用户选定的 B 方案：白色主体、简约留白、石墨按钮、少量紫色强调。以事项和工作活动组织功能；一个参与者可以编写、规划、开发及验收，不创建产品经理／研发岗位身份，不设置视角切换或不同岗位工作台。现有系统管理员身份及有效权限继续管理访问与操作。

本次重写 UI skills，不依据之前的 skills 或现有交互布局设计。已有业务契约、账号归属、权限、会话身份和数据安全边界继续有效。

## 完整协作链路

1. 创建需求或缺陷，填写目标、描述、验收标准／复现步骤及附件，讨论后确定版本和优先级。
2. 认领或指派产生待开发任务；不克隆仓库、不创建 Worktree、不执行 Agent。
3. 执行者整理范围，只合并本人、同项目、同版本、尚未启动的任务；保留来源关系。
4. 准备个人空间，从实时远端分支目录选择基线，明确点击开始开发。原型分支为演示数据，正式实现不得退回手输或本地缓存。
5. 在本人 AI 会话中沟通、审批、查看代码和验证结果；项目成员能读事项不等于能读其他人的会话。
6. 明确发布可共享交付，公开的是所选说明、文件与提交信息，不公开整段私人会话。
7. 核对验收标准，明确通过或填写退回原因；Agent 返回成功、任务完成及业务验收是不同状态。
8. 满足事项及任务结束门禁后归档版本。历史删除与工作目录清理分别确认，不变更已有身份或路径。

独立开发保留独立入口，提交目标和分支后显式开始，不强制关联事项或版本。结果不明时查询原请求，不重新派发。

## 屏幕与响应式契约

尺寸以 **CSS 视口** 衡量；1920×1080 显示器在系统缩放下可能只有 1536×864 CSS 像素。像素密度只影响清晰度，不用于计算岗位或布局模式。

| 验收视口 | 布局目标 |
| --- | --- |
| 2560×1440（2K/QHD） | 固定字号，常规内容最大 1600px；代码／会话工作区最大 1920px，合理使用辅助信息，不无限拉长文本 |
| 1920×1080（1080P） | 208px 主侧栏，舒适内容留白，正文和辅助区独立分配宽度 |
| 1440×900、1280×720 | 不整体缩放；信息重排，长页正常滚动，主动作始终可达 |
| 768×1024 | 紧凑图标侧栏，详情由左右分栏转上下内容；不强行挤三栏 |
| 390×844、320×740 | 单列，抽屠菜单及底栏；列表转条目，长代码局部滚动；主要点击区域至少 44px |
| 低高度、200% 缩放、DPR 2 | 不遮住表单提交与对话输入，内容不出视口；触控和键盘均可完成主流程 |

页面字号不是效果图缩放结果：正文 14–16px、辅助至少 12px、标题 28–32px。表单正文约 760–880px，详情辅助区约 300px。布局用流式网格、内容驱动高度和断点，禁止用 `transform: scale()`、CSS `zoom` 或固定 1536px 画布模拟适配。

生成图中偶发的文字、日期、模型名及按钮状态不作为业务契约。例如 Agent 运行时不能再次出现可用的“开始开发”；正式交互以实际状态为准。

## 组件与状态

支持简体中文与英文，入口覆盖登录、首次改密、初始化和主工作台，默认中文并记住本机选择。语言切换即时生效且不重置草稿、会话或筛选，不触发保存。用户内容、自定义流程和执行记录保持原文，已知界面反馈翻译，未识别的服务／Agent 诊断保留原文。

- 统一壳层、页面标题、上下文选择、列表行、状态标记、表单分区、详情辅助区、抽屉、确认弹窗、会话输入和消息反馈。
- 表单错误邻近字段，保存失败保留草稿；加载和空状态保持页面骨架；权限失效清理受限内容。
- 编辑冲突保留草稿和最新版本，字段级选择后保存。运行结果不明只查询原请求。
- 模态界面支持焦点限制、Escape、焦点返回；列表行操作有独立可访问名称；色彩之外同时提供文字／图标状态。
- 移动端固定操作区预留 `safe-area-inset-bottom`，使用动态视口；弹窗内容及页尾都能滚动到达。

## 原型与现有能力的区别

此轮原型覆盖全部 48 张参考图对应的主页面和关键状态，移动图对应同一响应式页面，不另建移动产品。低频设置及外部动作以浏览器内模拟结果展示。刷新可重置演示；密码和密钥不写入浏览器持久化，不接入真实 Git、Agent、MCP 或数据库。

正式实现新增 `/api/workbench/issues|tasks|deliveries` 聚合与搜索接口，开发队列只显示本人任务。交付发布、详情和验收走项目授权接口；日期、标签已进入事项模型。原型为视觉与交互参考，真实边界以[实施记录](ui-refactor-implementation.md)为准。现有项目、任务和工作区深链继续可达。
