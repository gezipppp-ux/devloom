# 项目协作与自动化开发 PRD

版本：1.4；日期：2026-10-12；状态：产品范围已确认，按实施清单逐项实现。项目直接引入仓库，不设归属部门和独立仓库目录；管理员全局管理项目协作，用户名登录、显示名称展示。需求／Bug 和开发任务的分支继承、启动确认及远端获取规则见[开发基线 PRD](./development-baseline.md)。

本文件描述目标版本，不代表当前代码已经具备全部能力。完成情况见[实施清单](./project-collaboration-implementation.md)。与现行工程契约冲突的行为，在对应功能落地时同步更新契约、实现和测试。

## 1. 目标与已确认决策

将个人需求执行工作台改造成以项目为中心的协作平台，覆盖需求／Bug 维护、人员协作、项目资产及 Codex 自动化开发。业务协作不依赖 Git 或 Codex。

| 编号 | 已确认决策 |
| --- | --- |
| D01 | 部门一级平铺，不设上下级；一个用户属于一个部门，项目不归属部门，支持跨部门成员。 |
| D02 | 普通成员由部门设定功能上限、项目成员关系限制数据范围、项目授权细化操作权限。管理员跨项目管理协作内容；代码、Agent、敏感资产及个人空间仍遵守原授权。权限不根据部门名称或岗位名称写死。 |
| D03 | 查看、维护、执行、审批等能力分别授权。产品部门默认不开放开发功能，但可由管理员调整部门授权。 |
| D04 | 系统管理员维护用户、部门和系统设置，能向指定用户授予创建项目权限。普通成员默认不能创建项目或个人工作空间。 |
| D05 | 新建项目直接引入一个 Git 仓库，填写地址即可，无需管理员预先登记仓库；仓库地址归项目管理，项目创建者为初始负责人。 |
| D06 | 获得开发执行权限的项目成员由系统分配开发空间；个人自行创建空间的能力默认关闭，后端拒绝未经授权的创建。 |
| D07 | 用户可维护多个个人 Git 账号；非开发用户不强制配置 Git。项目仓库地址、个人 Git 认证凭据与提交作者身份分别管理。 |
| D08 | 项目资产包括备忘录、文档／附件、环境地址、非生产账号密码、Token／密钥；不包含生产凭据，不接入 Codex。 |
| D09 | 需求、Bug、评论、交付结果归项目所有，按权限访问。业务事项与开发执行任务分别建模。 |
| D10 | 原生创建、TAPD 只读导入、手动快速输入统一进入项目事项管理，保留多条需求融合开发。 |
| D11 | 首期采用固定需求／Bug 流程；创建、分派、状态变化不自动启动 Codex；执行结束不自动验收或关闭事项。 |
| D12 | 新部署使用 PostgreSQL + Prisma；保留 CommonJS 业务模块，增加生成客户端的构建步骤。 |
| D13 | 不迁移现有数据，不导入旧 SQLite；旧数据库、源码、工作目录和会话资料保留原位，不自动清理。 |
| D14 | 用户名唯一且用于登录；显示名称独立保存，允许中文和重名，由管理员或账号本人修改，改名不改变身份和目录。 |

## 2. 首期范围

包含部门与权限、项目与成员、项目仓库引入、个人多 Git 账号、自动分配开发空间、需求与 Bug、评论／附件／交付、项目资产及现有自动化开发能力的项目化接入。

后续扩展项：部门层级、多部门任职、多仓库项目、自定义工作流、迭代与工时、TAPD 双向同步、无人值守自动合并／发布、生产凭据托管、资产与 AI 集成、对不互信租户的操作系统级隔离。

首期依然面向受信任团队。应用权限限制接口访问，不能宣称共用服务器系统账号的执行程序具备租户级文件和进程隔离。

## 3. 核心模型

| 实体 | 归属及约束 |
| --- | --- |
| 部门 | 名称唯一、平铺结构，组织用户并维护权限上限；有用户引用时不能直接删除。 |
| 用户 | 唯一用户名、显示名称、一个部门、系统角色、账号状态及个人设置；系统管理员无部门也可管理项目协作，开发与敏感字段权限仍由部门限定。 |
| 项目 | 名称、说明、负责人、一个 Git 仓库地址、状态及项目配置；不归属部门、不保存个人访问凭据。目录和身份使用稳定 ID，名称可重复。 |
| 项目成员 | 项目与用户唯一组合，保存有效状态和权限集合；可使用预设权限模板快速分配，服务端按具体权限判断。 |
| 个人 Git 账号 | 用户所有，保存认证方式、适用 Git 主机、账号说明及加密凭据；可配置多个。 |
| 开发空间 | 项目与用户唯一组合，保存仓库副本、凭据绑定、准备状态；项目成员关系是业务授权来源。 |
| 业务事项 | 需求或 Bug，拥有项目内编号、内容、业务状态、负责人、版本及来源。 |
| 开发任务 | 项目、执行空间、执行人、原生会话、分支与 worktree；与业务事项通过关联记录连接。 |
| 事项来源 | TAPD 的渠道、外部项目 ID、事项类型与编号及快照；同一项目内唯一。 |
| 项目资产 | 类型、标题、内容、分类、标签、环境、负责人、修订号和时间；敏感内容独立加密。 |

一条事项可以关联多个开发任务，一个开发任务可以融合多个事项。同一事项重复导入复用业务记录，不以“事项只能有一个任务”的约束阻止拆分开发。

仓库信息只属于项目，不存在共享的仓库目录记录。项目和用户 ID 参与本地路径及任务身份计算，不能因地址或名称相同而发生目录碰撞。

## 4. 权限规则

### 4.1 授权范围

系统管理、个人创建项目资格、项目内业务操作分开判断。

- 系统管理员无需所属部门或项目成员关系，即可创建项目、查看全部项目（含归档），管理成员、配置、需求／Bug、评论、交付和普通资产。归档写保护、负责人交接和最后有效管理员保护继续生效。
- 管理员全局权限采用显式名单，在普通成员权限依赖闭包计算后并入，不为代码、Agent 或敏感字段补齐依赖。个人开发空间始终校验所有者；管理员身份不授予他人空间访问权。
- 非系统管理员创建项目需要管理员授予创建资格，且所属部门允许创建项目；创建时不选择部门，不设置项目所属部门范围。
- 普通成员的项目操作，以及管理员的代码、Agent、敏感字段操作，同时要求有效账号、有效项目成员关系、部门允许该功能、成员在项目中获授该权限。
- 项目负责人管理成员和项目，但不能突破成员部门的权限上限，也不能因负责项目自动使用 Codex 或读取敏感资产。
- 授权模板只是配置便利，不使用“产品部”“研发部”等文本作为权限条件。
- 权限变更、成员移除、账号停用后，拒绝后续请求并撤销对应 SSE／订阅；异步操作完成发布前复核授权。
- 撤权后不自动删除工作目录或历史。已启动的外部操作不能被描述为已撤销；禁止新轮次与新网络操作，已有活动执行请求受控停止并记录实际结果。

### 4.2 权限清单

| 范围 | 权限项 |
| --- | --- |
| 系统 | 用户管理、部门管理、系统配置、审计查看 |
| 项目 | 查看项目、创建项目（个人资格与部门功能上限）、修改配置、管理成员、归档项目 |
| 需求／Bug | 查看、新建、编辑、分派、状态流转、验收／验证 |
| 协作 | 查看评论和交付、发表评论、发布交付结果 |
| 代码 | 查看代码与差异、执行仓库操作 |
| Codex | 查看会话、启动任务、继续对话、处理审批、停止执行 |
| 资产 | 查看普通资产、维护资产、查看敏感字段、维护敏感字段 |

查看权限与写权限分别校验。启动、继续、批准 Codex 执行可能运行命令和修改代码，应校验必要的代码执行能力，并在授权界面解释依赖。没有权限的入口不显示或明确说明无权；直接请求接口仍必须被拒绝。

项目事项列表、附件、全文搜索、导出（如实现）、图片和 SSE 使用相同数据边界；不可通过子资源 ID 绕过项目授权。

### 4.3 人员生命周期

移出项目保留历史作者和交付信息，取消普通成员后续项目访问和开发执行权限；管理员仅保留全局协作管理权限。重新加入恢复原有成员／空间身份，避免重复克隆。负责人离开前需指定有效成员接任；项目不能无负责人。部门调整后重新计算成员权限，管理员降级后立即恢复普通成员规则。

## 5. 项目与开发空间

创建项目时直接填写 Git 仓库地址、项目名称和说明，创建后分配成员。项目不设置归属部门，也不提供按所属部门限制的创建入口；普通成员所属部门仍限定创建和参与项目时的功能上限，管理员创建不要求部门。Git 地址支持 HTTP(S) 和 SSH，不接受嵌入密码／令牌；创建只校验字段，不要求创建者提供 Git 账号，不触发克隆或 Agent。项目配置管理仓库地址、默认开发分支、初始化命令、提示词和 TAPD 来源配置；个人设置保留模型、通知等偏好。

有开发执行权限的成员自动获得空间记录。首次使用前完成 Git 凭据绑定和仓库访问检查，再异步克隆；未就绪时显示“待配置 Git／准备中／可用／失败”，支持明确重试，不静默使用管理员凭据。

没有开发权限的成员直接使用项目需求、Bug 和资产，不经过 Git 配置，不产生代码克隆。前端不能通过提交用户 ID、目录或仓库地址创建任意个人空间。

凭据检测与克隆在数据库事务外执行；受理和发布分别使用短事务及幂等标识。重启不自动重放不确定的任务或删除不确定目录。成员根目录使用 `projects/<项目ID>/members/<用户ID>`，每次受理准备使用独立的 `repository-<准备修订号>` 子目录；同一请求幂等，失败后的明确新请求使用新目录并保留原文件，已就绪仓库路径不变。项目重命名、成员改名、安装路径改变均不移动已有 worktree。

仓库地址在项目产生开发空间后不可直接替换；项目设置显示只读地址及锁定原因，其他配置可照常保存。防止历史会话连到错误仓库。归档项目保留历史、停止新建开发任务。

## 6. Git 账号

个人 Git 账号不再和单个仓库地址捆绑。支持 HTTP(S) 令牌／密码及 SSH 密钥，用户对项目仓库选择自己的账号。连接检测针对实际选定仓库，平台项目权限不替代 Git 服务授权。

Git 凭据由本人配置；管理员可创建用户，但不要求代填用户密码或私钥。无开发能力的用户可跳过 Git 引导。访问凭据和提交作者姓名／邮箱分别配置；不能以 Git 登录名自动冒充提交作者。

凭据加密存储，不出现在公开响应、URL、进程参数、仓库配置或日志中。被空间引用的账号不能直接删除；轮换使用修订号，避免迟到检测覆盖新凭据。凭据仅注入对应执行上下文，不共享其他成员凭据。

## 7. 需求、Bug 与协作

### 7.1 字段

通用字段：项目内编号、类型、标题、描述、优先级、负责人、参与人、状态、附件、创建人与时间、更新人与时间、来源、修订号。所有人员必须是有效项目成员；离开的历史人员仍能展示姓名记录。

需求增加验收标准。Bug 增加复现步骤、预期结果、实际结果、严重程度。评论和交付结果独立记录作者与时间；交付可关联开发任务及提交信息。

更新使用修订号防止静默覆盖并发修改。记录字段、负责人和状态变更历史。

### 7.2 固定状态流转

需求主流程：待评审 → 待开发 → 开发中 → 待验收 → 已完成。

Bug 主流程：待确认 → 待修复 → 修复中 → 待验证 → 已关闭。

补充分支：评审／确认阶段可驳回；未完成事项可取消；验收失败回到开发中，验证失败回到修复中；有权限者可重新打开已完成／关闭事项并填写原因。非法跳转由后端拒绝。验收／验证是单独权限，不因能编辑描述自动获得。

### 7.3 来源与执行

平台创建和手动输入建立本地事项；新增与编辑共用完整字段，标题必填，其他内容可选，不要求立即分配或执行。需求支持验收标准；Bug 在首次创建时即可填写复现步骤、预期结果、实际结果和严重程度。

描述、验收标准、复现步骤、预期结果和实际结果默认使用图文可视化编辑：粘贴图片后直接在正文显示，可以在图片前后继续输入，支持常用格式与撤销／重做。可切换 Markdown 源码和只读预览；保存格式仍为 Markdown，无法无损转换的特殊语法保留原文并提供源码编辑。图片／普通附件可多选，待保存区显示缩略图或文件卡片。附件先保留在本页草稿中，与事项内容一起保存；取消不产生服务器孤儿文件，保存失败或修订冲突保留草稿和附件。每个附件最多 10 MiB，每次保存新增附件最多 20 个、合计 20 MiB。详情安全展示已授权的本事项图片，普通附件提供下载；不自动加载 Markdown 中的远程图片。

TAPD 导入保留原始渠道标识、外部类型与编号、链接、快照及导入时间。项目内重复导入返回已有事项；再次抓取不能无提示覆盖本地维护字段。首期不向 TAPD 回写状态、人员或内容。

启动开发需要显式动作、开发权限、可用空间与有效 Git 凭据。启动时保存事项内容快照，后续事项编辑不偷偷改变已执行的提示词；追加资料沿用显式发送和幂等控制。

事项业务状态、任务人工进度、Codex 执行状态分别持久化；运行完成不自动变为已验收，任务失败不自动关闭或取消事项。

## 8. 项目资产

| 类型 | 主要内容 |
| --- | --- |
| 备忘录 | Markdown 说明、注意事项和决策记录 |
| 文档与附件 | 操作说明、原型、图片、交付资料 |
| 环境地址 | 开发／测试环境链接、服务与接口说明 |
| 非生产账号密码 | 服务名称、登录地址、用户名、加密密码 |
| Token／密钥 | 用途、非生产环境、加密值、有效期（可选） |

资产支持分类、标签、负责人、更新时间、历史记录、关联需求／Bug。统一显示元信息，敏感字段按权限显式读取；普通列表、搜索、历史差异和 API 响应不返回密文解密结果。

敏感内容使用认证加密，密钥与数据库分开保管。访问和修改记审计，但审计内容不含明文。敏感历史如保留也必须加密。首期不提供生产凭据资产类型。

资产不提供 Codex 引用、自动检索或上下文注入接口。需求附件和项目资产附件具有各自资源归属，不能借资产 ID 伪装为开发任务附件。

## 9. 页面与交互

全局入口：管理员显示「全部项目」，普通成员显示「我的项目」，所有账号可进入个人设置；有系统权限时显示部门／账号管理、系统设置。新建项目直接引入仓库，不设独立仓库目录页面。

项目入口：概览、需求、Bug、开发任务、代码与环境、资产、成员与设置。各入口及操作按有效权限显示。无项目时按管理员配置进度或成员等待分配分别引导；创建入口与后端使用一致的资格前提。新建项目先引导负责人为本人及成员分配工作，不自动授予开发权限。

部门页面以“可用功能”设置能力上限，项目成员页面以“工作内容组合”授予具体操作，两者不重复展示默认的细项清单。部门可按项目管理、需求与 Bug 协作、代码操作、Codex 开发、普通资产、敏感资产开放能力；项目可添加产品协作、代码操作、Codex 开发、项目管理组合，并展开高级权限细调。组合叠加保留已有管理权限；部门未开放组合核心能力时禁止添加并说明原因。活跃成员至少获得查看项目，已移除成员通过恢复操作复用原关系。

事项、开发任务、资产详情通过包含对象 ID 的地址恢复，支持刷新、分享和浏览器前进/后退。事项详情直接提供授权后的开发入口；首次准备个人 Git/空间时保留来源事项，准备完成后仍需显式确认启动。开发会话返回原来源，显式指定的会话缺失时不得自动替换为其他会话。

刷新同一对象和切换评论/交付标签保留未发送草稿；提交完成只清理对应请求的内容。编辑冲突提供加载最新、保留草稿及逐字段合并，不能只换修订号覆盖他人修改。资产详情呈现关联事项、负责人和有效期，历史独立分页并使用可读的变更说明。

需求／Bug 详情集中显示描述、状态、负责人、评论、附件、历史和关联开发任务。Codex 会话、原始命令和日志只有相应权限者可见；项目业务结果不以原始会话代替。

沿用仓库浅绿工作台设计体系。覆盖桌面／移动端、加载／空／失败／无权／已归档状态，以及账号、项目切换后的迟到请求和订阅清理。

## 10. 技术与部署

- 使用 PostgreSQL + Prisma，CLI、客户端、PostgreSQL adapter 固定为一致的稳定版本；不用候选版或无界版本。
- Prisma schema 和迁移归 storage，生成产物不手改；客户端生成与编译纳入安装／构建和 CI，CommonJS 业务模块继续沿用。
- application 负责授权、用例和 presenter；HTTP 不直接调用 Prisma，执行模块不嵌入 TAPD 或项目资产逻辑。
- 全部生产存储按异步访问改造，不用同步阻塞桥接或内存缓存冒充数据库。生产不回退 SQLite，不并行维护两套权威数据源。
- 生产部署使用版本化迁移；不执行 db push、reset 或破坏性自动降级。升级失败拒绝启动；事务不跨越 Git、网络或 Codex 等待。
- 数据库连接使用环境配置，不输出连接密码。凭据主密钥仍独立于数据库保存。采用独立新数据库和运行目录，不修改旧数据库或工作树。
- 测试使用隔离 PostgreSQL、fake Codex、模拟 TAPD、临时 Git；不得使用真实业务执行或生产库验证。

## 11. 验收标准

| 编号 | 场景与预期 |
| --- | --- |
| AC01 | 多个平铺部门可创建和维护，不能配置父部门；用户只关联一个部门。 |
| AC02 | 产品权限模板成员可维护事项，无开发入口；伪造 Codex／Git API 请求仍被拒绝。 |
| AC03 | 成员项目授权超出部门上限时保存被拒绝；部门撤权后已打开页面和 SSE 不继续取得相关数据。 |
| AC04 | 普通成员无法创建项目／个人空间；指定创建者直接填写 Git 地址创建项目并成为初始负责人，不依赖管理员登记仓库；旧仓库目录及接口不可用。 |
| AC05 | 跨部门成员按授权协作；普通非成员无法按项目、事项、附件或会话 ID 越权读取。管理员可跨项目管理协作，但不得因此读取敏感字段或他人的个人开发空间。 |
| AC06 | 开发授权自动分配且不重复建立空间；无开发授权者无需 Git；凭据未配置时不开始克隆。 |
| AC07 | 多 Git 账号可绑定不同项目，检测实际仓库权限；账号秘密不会进入公共响应或其他用户执行环境。 |
| AC08 | 一条事项可关联多个任务，多条事项可融合执行；每次执行使用保存的内容快照。 |
| AC09 | 新建、分派和状态修改不启动 Codex；执行结束不自动完成需求或关闭 Bug。 |
| AC10 | 非法状态跳转被拒绝，验收失败可退回；并发编辑不会无提示覆盖。 |
| AC11 | 重复导入同一 TAPD 事项不重复建记录，不回写上游，不静默覆盖本地字段。 |
| AC12 | 资产支持规定类型、关联、版本和权限；无敏感权限者无法取得明文，审计不泄漏明文。 |
| AC13 | 项目资产不进入 Codex 上下文，开发任务不能借附件 ID 读取项目资产。 |
| AC14 | 成员移除失去访问，历史作者、任务和路径仍保留；负责人移除需先接任。 |
| AC15 | 全新 PostgreSQL 可初始化、升级和启动；失败不给出成功状态，业务持久化不依赖 SQLite。 |
| AC16 | 旧数据目录内容与已有 worktree 不被迁移、覆盖、清理或重新执行。 |
| AC17 | lint、架构／单元／集成测试、构建及 Jenkins 浏览器检查通过；界面截图通过人工检查。 |
| AC18 | 无部门、未加入项目的管理员可从「全部项目」管理配置、成员与协作内容；取消管理员角色后不保留全局权限，归档与负责人保护有效。 |
| AC19 | 用户名登录、显示名称展示；管理员及本人可改显示名称，重名可由用户名区分，改名不退出登录或改变目录，迟到响应不覆盖其他账号及新权限。 |
