## 1. 已确认的范围

| 项目 | 用户已确认的要求 |
| --- | --- |
| 配置归属 | 系统级配置，由管理员维护，不提供个人供应商维护入口 |
| Agent | 首期只实现 Codex，为 Claude 等其他 Agent 保留扩展边界 |
| 认证 | API Key；保留管理员可选的“服务器现有配置”，不新增官方网页登录 |
| 管理 | 新增、编辑、复制、删除、启用、停用和设置默认供应商 |
| 字段 | 名称、API 地址、API Key、备注、模型及思考强度 |
| 模型 | 手动填写、从供应商接口获取 |
| 检测 | 管理员手动发起连通检测，允许最小测试请求产生少量费用 |
| 切换 | 已有会话下一轮使用新供应商，当前执行轮次不中断 |
| 失败 | API Key 供应商失败时不自动回退到服务器现有配置 |
| 协议 | 不实现路由转换 |

以下为本方案建议的具体规则，随方案一起确认。首期不扩展到供应商预设市场、导入导出、余额与费用统计、自动测速、故障转移、聚合路由，以及 MCP／Skills／提示词管理。

## 3. 页面与使用方式

### 3.1 系统设置 → Agent 供应商

增加 `/system?tab=agent-suppliers`，沿用系统设置的分类导航、页面宽度及浅绿工作台样式。首期只展示 Codex；扩展点保留在数据和适配接口中，不提供尚不可用的 Claude 配置表单。

列表展示名称、认证来源、API 地址、默认模型、启用状态及“当前默认”标记。API Key 只展示“已配置”，读取接口不返回明文。管理员可新增、编辑、复制、检测、设为默认、停用和删除。

“默认供应商”就是该 Agent 的系统当前选择，不另设含义重叠的“当前供应商”开关。普通成员无需选择供应商，所有会话的新轮次跟随系统选择。

编辑表单分三组：

1. 基础信息：名称、备注、启用状态。
2. 连接信息：API 基础地址、API Key。编辑时不回填密钥，未提交新 Key 表示保留原值。
3. 模型配置：模型 ID、显示名称、支持的思考强度、默认模型及默认强度；提供“获取模型”与手动增删入口。

复制生成未启用、非默认的新条目，复制基础信息和模型配置，重新填写 API Key。保存只做校验和持久化，不自动检测、不启动会话。

### 3.2 会话与启动页面

- 启动页面显示系统当前供应商名称，保留现有模型、思考强度与执行权限控件。
- 会话显示“本轮供应商”和有变化时的“下一轮供应商”，普通成员仅看到名称及与执行相关的模型信息，不读取管理地址、备注或密钥。
- 管理员切换后，运行中的会话提示“下一轮使用 XXX”，不打断输出、审批或当前轮次的补充指令。
- 模型目录随下一轮供应商更新；保留输入草稿、附件、滚动位置和当前会话身份。
- 页面分别处理加载、空列表、保存、模型获取、检测及失败状态；离开页面、切换账号或切换编辑对象后忽略迟到响应。

### 3.3 内置“服务器现有配置”

- Codex 提供一个不可删除的内置选项，初始化时作为系统默认，保持首次启用该功能前的使用方式。
- 该选项继续使用服务账号原有 Codex 配置与认证，不导入或展示本机密钥，不提供 Web 登录／登出操作。
- API Key 模式通过独立运行配置生效；管理员显式切回内置选项时，下一轮重新按原生配置恢复会话。
- 内置选项的模型来自 Codex；API Key 模式的模型来自供应商配置，两类目录与缓存分开。
- 内置选项仅复用已有的环境、登录及模型读取检查；不将这些检查称为 API 生成成功。

## 4. 切换与轮次规则

### 4.1 保留身份，切换连接配置

每个会话的执行连接按需创建、独立持有、空闲回收。工作区管理器继续负责授权与任务协调，模型发现使用独立、可回收的连接，不占用或重置执行中的会话连接。

每个新轮次进入启动操作临界区时，读取并冻结系统选择、供应商配置修订号及凭据修订号。切换后受理的轮次使用新配置；已经受理并开始准备的轮次继续使用其冻结配置，界面保留可核对的本轮信息。配置读取和启动之间发生冲突时，在尚未发送轮次前重新校验，不对已发送请求自动重放。

轮次边界定义如下：

| 场景 | 行为 |
| --- | --- |
| 首次启动 | 使用当时的系统当前供应商，记录初始脱敏快照 |
| 正在输出 | 当前轮次继续使用已冻结的供应商及 Key |
| 等待审批／提问 | 响应交给原连接，不因系统切换改写归属 |
| 运行中补充指令 | 仍属于当前轮次，使用原连接进行 steer |
| 下一轮发送 | 检查最新系统配置，必要时重建本会话连接，恢复同一 session 后发送 |
| 连续切换 A → B → C | 尚未受理的下一轮直接采用 C，不依次启动 B |
| 服务重启／断线 | 保留历史与身份；人工继续时读取最新系统选择，不自动执行 |
| 切换或恢复失败 | 显示错误并保留草稿／历史，不创建替代 session、不重放、不回退供应商 |

重建连接前必须确认本会话无运行轮次、未完成交互、启动操作及待落库事件。释放并关闭旧连接后，按原 `session_id` 和 cwd 恢复。未知原生执行状态阻止切换与发送，不能当作空闲。

会话 ID、run key、source、分支和 Worktree 路径保持原值，不搬迁 Codex 会话文件或业务目录。其他任务的连接及 Git 凭据生命周期不受此次切换影响。

### 4.2 模型与执行权限

- 未显式指定模型时，使用当前供应商的默认模型；未显式指定强度时，使用该模型已配置或原生返回的默认值。默认值未知或不在支持范围内时阻止发送并提示配置或重选，不能继承上一轮强度。
- 用户显式选择的模型／强度若仍受新供应商支持，则保留；若不支持，阻止下一轮发送并提示重新选择，不静默替换。
- 个人默认模型继续作为用户偏好，按当前供应商校验；系统供应商切换不批量改写个人设置或任务初始快照。
- 执行权限仍由 Agent 原生能力与用户现有选择控制，供应商配置不提升执行权限。
- 原始创建快照保持不变，另存每轮实际供应商、配置版本、模型与强度的脱敏快照，区分初始值、本轮值与下一轮目标。

### 4.3 编辑、停用和删除

- 修改地址、Key、模型目录或默认执行参数生成新的运行配置版本；当前轮次继续旧版本，下一轮读取新版本。只改名称／备注不强制重启执行连接。
- 当前默认供应商不能直接停用或删除；管理员先显式切换到另一启用选项，不自动挑选替代供应商。
- 非默认供应商停用后不接受新轮次；已经开始的轮次正常结束。
- 运行中、等待交互或执行状态不明确的轮次仍引用供应商时，禁止删除并说明原因。只有历史快照引用时允许删除，历史名称与版本仍可显示。
- 并发编辑／切换使用修订号与短事务，冲突返回 409 并保留页面草稿。

## 5. Codex 接入方式

### 5.1 原生直连

API Key 供应商必须提供 Codex 可直接使用的 Responses 接口。只有 Chat Completions 或 Anthropic 接口的服务不通过本功能转换；地址即使指向用户已有的兼容网关，本应用也不承担转发与协议转换。

Codex adapter 生成专用的原生 `model_providers.<id>` 配置，以 `base_url`、`wire_api = responses`、`env_key` 等描述直连。Key 仅注入对应子进程环境，启动参数只包含环境变量名和非秘密配置，避免 Key 出现在进程参数中。

配置仅在本应用持有的进程／会话中应用，不写共享 `config.toml`、`auth.json`，不切换 `CODEX_HOME`，不改写其他 Codex 客户端的默认供应商。恢复原会话时显式提供目标供应商及模型覆盖，避免继承旧会话供应商。

“服务器现有配置”使用原生配置解析结果，不强制将其等同于 OpenAI 官方登录；服务器也可能已有自己的合法原生供应商配置。

### 5.2 模型目录

- “获取模型”由服务端使用当前编辑草稿或已保存配置请求供应商的模型列表，结果供管理员选择后保存，不自动覆盖整份已配置目录。
- 获取失败／不支持模型列表时保留手填能力。列表获取成功只证明列表接口可用，不等于模型能完成生成。
- 普通模型列表通常不含思考强度、图片能力等完整信息；仅使用接口明确给出的元数据、Codex 已知目录或管理员显式配置，不从模型名称猜测。
- Codex 专属目录转换由 adapter 完成；若安装版本要求模型目录文件，由 storage 写入受控派生缓存，数据库仍为权威来源。
- 实施时检查本机 Codex 的只读协议 schema 和目录格式；能力缺失须给出明确版本／配置错误，不能绕过原生模型校验。

### 5.3 连通检测

- 只由管理员显式触发；可检测未保存的编辑草稿，检测不隐式保存。
- 对所选 API Key 供应商和模型发送固定、无业务资料的最小 Responses 请求，限制输出、超时和响应体大小，不携带真实任务、图片或仓库内容。
- 显示请求结果、耗时及经过脱敏的失败类别；校验协议和生成结果，不以 TCP 可达或 HTTP 200 冒充生成成功。
- 获取模型与生成检测分别展示结果。检测失败不自动停用、切换供应商或改变任务状态；检测成功也不承诺所有模型工具能力可用。
- 网络等待不占数据库事务。等待结束重新检查管理员身份及配置版本，过期结果不覆盖新配置。

## 6. 数据、权限与接口

### 6.1 数据结构

新增三类系统数据，具体字段以 Prisma schema 为准：

| 数据 | 主要字段与约束 |
| --- | --- |
| `AgentSupplier` | 稳定 ID、agentType、mode（api-key／server-config）、name、baseUrl、加密 credentials、notes、models、默认模型／强度、enabled、revision、运行配置版本、时间戳 |
| `AgentSupplierSelection` | 每个 agentType 一条当前供应商引用、选择修订号；只允许引用同类型、启用且完整的配置 |
| `AgentSupplierUse` | 工作区／run key、供应商引用、轮次租约及使用状态；与供应商删除检查互斥，任务永久删除时原子清理 |

模型数组为受校验的结构化数据，不接受任意 TOML／启动参数／命令。密钥复用 `database-secrets.cjs` 的 AES-256-GCM 和既有主密钥生命周期；编辑省略 Key 保留原值，显式空值拒绝保存。

执行记录通过现有 RunStore 增加轮次供应商快照及当前应用版本，不记录 Key、原始认证头或完整原生配置。历史快照不因删除供应商而级联删除。

在当前部署基线后添加版本化迁移，不改写已发布基线；默认数据幂等创建内置服务器配置。仅为当前系统记录添加本功能字段，不导入早期废弃数据库或修改已有任务身份。

### 6.2 API 草案

管理员接口位于 `/api/system/agent-suppliers`：

| 方法／路径 | 用途 |
| --- | --- |
| `GET /api/system/agent-suppliers?agentType=codex` | 脱敏列表、当前选择及管理能力 |
| `POST /api/system/agent-suppliers` | 新增 |
| `POST /api/system/agent-suppliers/:id` | 带 revision 编辑／启停 |
| `POST /api/system/agent-suppliers/:id/duplicate` | 生成不含 Key 的复制草稿 |
| `POST /api/system/agent-suppliers/:id/activate` | 带选择修订号设置系统默认 |
| `POST /api/system/agent-suppliers/:id/delete` | 引用检查与显式确认后删除 |
| `POST /api/system/agent-suppliers/models` | 获取已保存配置或草稿的模型列表 |
| `POST /api/system/agent-suppliers/check` | 检测已保存配置或草稿 |

普通成员通过现有执行选项和会话响应读取必要的当前／下一轮供应商摘要及可用模型，不开放供应商管理接口。系统级配置不要求先选择工作区；会话操作继续检查所有者和项目权限。

所有写接口复用登录、CSRF、正文限制及权限复核。API 地址只接受 HTTP(S)，拒绝 URL 内嵌凭据；带 Key 请求不跨站重定向。凭据不进入公开响应、模型缓存键、错误正文或日志。现有系统仍共享服务账号，不能将子进程环境隔离描述为操作系统租户隔离。

## 8. 实施顺序与验收

1. **核实适配能力**：只读验证已安装 Codex 的 start/resume 配置覆盖、模型目录和命令参数能力；以 fake Codex 增加跨供应商恢复契约用例。若必要接口不支持，先说明具体限制并修订方案，不换 session 规避。
2. **数据与管理接口**：迁移、内置选项、凭据加密、管理权限、CRUD、当前选择和修订冲突。
3. **会话接入**：按会话管理连接、下一轮配置解析、原 session 恢复、模型目录、Git 凭据释放及事件归属。
4. **管理与使用界面**：系统设置页、编辑／复制／删除、模型获取、连通检测及会话提示。
5. **回归与文档**：更新工程契约、使用说明与部署说明，完成仓库要求的验证。

核心验收：

- A 的轮次执行中切换 B，当前输出、审批及 steer 仍属于 A；下一轮使用 B 且 session、Worktree、source 不变。
- 同工作区任务一运行时，任务二可按最新供应商开始下一轮，不能重启或断开任务一。
- A → B → C、编辑当前 Key、停用非默认供应商、重启后续聊均符合轮次与修订规则。
- API Key → 服务器现有配置 → API Key 可切换；失败不隐式回退或新建会话。
- 模型不兼容、连接失败、审批未完成、未知执行状态和迟到事件均不会触发重复轮次或错误归属。
- 管理员权限、成员 DTO、数据库／日志／进程参数均无密钥回显；并发编辑和删除引用保护有效。
- 模型获取失败仍可手填，连通检测不包含业务资料，表单保存不产生外部生成请求。
