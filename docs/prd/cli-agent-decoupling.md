# CLI Agent 解耦

本轮将已接入的 Codex 从项目协作、需求来源和通用执行生命周期中隔离。只实现 Codex 适配器，不接入 Claude CLI、pi，也不假定它们支持 Codex 的协议或能力。

## 产品与数据边界

- 项目、部门、成员、需求、Bug、资产、交付和代码权限保持既有规则。
- 需求渠道负责来源与资料快照；执行器负责执行。两者独立组合。
- 通用执行层负责仓库、工作树、初始化、锁和状态；应用层负责授权、会话生命周期、持久化及公开 DTO。
- Codex 适配器负责命令定位、子进程、原生协议、输入和事件转换、模型、执行权限与交互响应。
- 新任务固定记录 `agent.provider` 与初始选择；缺少该字段的旧记录不兼容。执行中的会话 ID、来源、工作树路径及分支不因适配层而改变。未知或不匹配的执行器拒绝执行，不能静默交给当前默认执行器。
- 配置仅使用 `execution` 和 `agent`；任务资料仅使用 `prompt`。不读取旧 `codex` / `codex_prompt` 字段，不迁移或删除旧业务数据。Git 凭据引用保护读取新配置。

## 接口

显式注册的 provider 创建会话适配器；业务层调用创建、读取、恢复会话，开始、追加、停止轮次，查询历史、模型和执行权限，响应交互、关闭连接。禁止通用层调用原生 `request(method, params)` 或加载浏览器提供的模块路径。

输入使用文本和已校验图片路径；事件使用会话/轮次标识、轮次开始/完成、展示条目/增量和请求已处理等含义。交互使用不透明 ID、`kind`、`blocking` 和所需展示字段，不向浏览器透传原生 RPC 方法、参数或 ID。图片只通过本任务的已保存记录匹配并生成授权 URL。

执行器显式声明能力；模型和权限选项由服务端提供。未知能力或查询失败不能当作支持，不支持的操作给出明确错误。当前只展示可用的 Codex，不增加无效的执行器选择入口。

## 必须保留的运行语义

真实执行开始事件才能触发来源流转；完成早于启动响应不能恢复旧轮次；首轮持久化结束前不启动下一轮；停止/关闭等待已受理工作并释放所属资源；凭据仅在空闲时刷新；断线不重放输入；现有数据库历史可离线查看。项目权限与执行器自身的命令审批是不同层级。

## 实施与验收

- [x] Codex adapter、显式注册表和标准事件/交互契约。
- [x] 通用执行配置、需求 prompt、Web 执行入口与显式注入会话接口的通用流水线。
- [x] 会话、历史、模型、设置、Git 空闲检查和账号查询改用 Agent 接口。
- [x] 前端移除原生 RPC 依赖，权限能力以服务端为准。
- [x] 架构约束、独立 fake Agent 回归、现有生命周期/浏览器回归。

验证使用 fake Agent、临时 Git 与独立 PostgreSQL；不执行真实需求、不调用真实 CLI Agent、不修改 TAPD。未来增加 provider 时需实现并验证实际能力映射，不能用自动同意或假成功补齐缺失能力。

实施结果、验证证据和测试夹具修正记录见[验收报告](../reviews/cli-agent-decoupling-2026-10-11.md)。
