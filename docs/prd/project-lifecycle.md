# 版本、流程与开发任务重构 PRD

日期：2026-10-12。生命周期功能已实施；本轮按补充要求将流程归属调整为系统设置，验证见[系统流程记录](../reviews/system-workflows-2026-10-12.md)。此前生命周期验收见[记录](../reviews/project-lifecycle-2026-10-12.md)。不兼容旧接口与旧业务数据格式，不为历史行为保留双轨逻辑。

## 已确认规则

1. 项目维护发布版本，需求／Bug 关联一个目标版本，可暂不排期。版本归档前，所有事项必须处于完成或取消状态，且没有未完成开发任务；否则先处理或移出该版本。归档后内容只读，恢复版本后可再编辑。
2. 本次开发基线只能从 Git 远端实时读取的分支中选择，支持搜索和刷新，不接受手输分支。开始执行时再次获取目标分支最新提交，固定 SHA 后创建 worktree。
3. 系统设置统一维护需求和 Bug 两套流程，仅系统管理员可以编排和发布。项目不拥有独立流程、覆盖配置或流程管理权限。图形编辑支持状态节点、连线、初始／完成／取消状态、可开发节点、操作权限和必填退回原因。草稿校验后发布为不可变版本，所有项目的新事项使用系统当前版本，已创建事项继续使用所绑定版本。
4. 指派／认领先创建待开发任务，不克隆、不创建 worktree、不调用 Agent。一个任务允许关联多个事项，一个事项同一时间只允许归属一个未结束开发任务，后端事务和数据库唯一约束同时保护。

## 交互与业务边界

默认需求模板按用户补充示例提供：规划中 → 开发中 → 待验证 → 验证中 → 已实现；另有已拒绝，以及退回开发、退回规划和重新打开的连线。默认 Bug 模板为待处理 → 处理中 → 已解决待验证 → 已验证待关闭 → 已关闭，另有失败待处理与已取消。两套都是可编辑的系统流程，不在执行器内硬编码流转；退回、拒绝及重开要求填写原因。

发布版本号（如 v0.2）独立于编辑修订号和流程定义版本。列表提供版本筛选，已归档版本默认隐藏，历史记录可查。

流程编排入口为「系统设置 → 流程编排」。项目仅展示事项绑定流程和允许执行的流转；状态筛选只能读取已发布版本，不向项目成员公开系统草稿。删除项目级流程页面、写接口和 `workflow.manage` 授权，不保留别名或兼容回退。系统流程发布的权限为管理员角色，事项流转的 `issue.transition`／`issue.accept` 继续按部门上限和项目授权执行。

需求／Bug 页提供“认领到开发任务”和“指派开发任务”，移除直接启动开发。认领人必须是具备开发资格的有效项目成员，但此阶段无需 Git 账号或就绪空间。指派者按事项指派权限操作，不能访问被指派人的个人会话。

开发任务先保存标题、执行人、关联事项与版本，支持执行前补充同版本事项、取消／释放认领和重新指派。启动后执行人、关联范围与本次基线不能静默改写；追加资料沿用明确保存和发送动作。任务完成／取消后释放活跃认领记录，保留历史关联。执行中的任务不能取消或转派；Agent 成功返回不等于业务验收通过。

“我的开发任务”中，执行人先准备个人空间，再从远端分支列表选择基线，点击开始开发。一个规划任务对应一次明确启动，重复请求不能产生第二个 worktree；失败或结果不明不得自动重放。个人会话继续保持所有者隔离，项目成员可查看计划、负责人、业务状态与公开交付。

任务和事项业务流程不与 Agent 的运行／失败状态混用。流程里的“验证失败／退回处理”表示业务判断；网络或 Agent 失败只记录执行失败。流程节点与连线具有稳定标识；删除被连线引用的节点须先处理连线。发布校验初始节点唯一、节点可达、存在结束节点、边两端有效、权限白名单及名称有效。

## 技术与验证

以独立版本、流程定义／发布版本、开发规划任务和活跃认领实体表达职责，清理 domain 中固定状态流转及前端硬编码状态选项。HTTP 只适配服务；Git 远端查询使用当前执行人的凭据，异步等待后重验权限，不写入凭据、不依赖本地缓存冒充实时结果。

保留数据库迁移版本管理，不修改已发布迁移。新模型不读取旧字段作为兼容回退；不会为本次验证执行真实需求或向 TAPD 写入。

实施顺序：模型与规则 → 版本及流程服务 → 认领／指派及显式启动 → 远端分支选择 → 页面与流程图 → 并发、权限、归档、快照及浏览器回归 → 本地更新。

验收重点：归档门禁及只读完整覆盖；流程发布不改在途事项；产品成员可规划协作而无 Agent 操作；并发认领只有一次成功；无 Git 时仍能认领；仅执行人能启动；分支列表来自远端、获取失败不降级手输；创建／认领／指派均不触发实际开发；窄屏图编辑、弹窗与底部操作可达。
