# 账号、项目协作与数据库

本契约取代生产环境中以工作区 JSON、上传目录和 JSONL 作为业务数据源的约定。Node.js CommonJS、Vue 和执行／渠道分层继续沿用。显式文件配置可作为 CLI 输入；生产工作区不导入或回退读取旧文件数据。

## 账号与归属

- 账号由管理员创建，不开放公开注册。角色为 `admin`、`member`；账号可停用，最后一个有效管理员不能被停用或降级。
- 初始管理员由服务器交互命令创建。账号名规范化为小写且全局唯一，当前不提供账号改名；密码统一为 6–256 个字符（含边界），适用于 Web 创建、重置、个人及首次改密，以及 CLI 初始化和重置；密码使用带随机盐的 scrypt。管理员创建或重置的成员密码首次登录须修改。
- 显示名称 `displayName` 与登录名 `username` 分开保存：显示名称去除首尾空白后为 1–80 个字符，允许中文和重名，不接受控制字符。页面展示名称，管理列表及人员选择同时展示用户名；用户名继续用于登录和身份定位。管理员可创建及修改显示名称，用户通过 `POST /api/account/profile` 仅修改自己的显示名称；单纯改名不增加 `authVersion`，不撤销登录或 SSE，也不改变已记录的工作目录。
- 普通成员属于一个平铺部门；部门限定功能上限，项目成员关系限定数据范围，有效权限为当前部门上限与项目成员授权交集的依赖闭包。管理员无需部门或成员关系即可查看所有项目（含归档），管理配置、成员、需求／Bug、评论、交付和普通资产；归档写保护仍生效。
- 管理员权限采用显式名单，只在普通成员权限闭包计算后并入，不为开发或敏感权限补齐依赖。代码、Agent 会话、敏感资产字段仍要求有效部门和成员授权；个人开发空间仍校验所有者。取消管理员角色后立即恢复普通成员规则。
- 项目不归属部门，只维护负责人、成员、仓库和业务内容。管理员可直接创建项目；普通成员的创建资格由账号资格与所属部门功能上限共同控制，不选择目标部门；同部门普通账号也必须加入项目才能访问。
- 项目只有一个负责人，负责人转移必须指定有效成员且保留项目查看、配置、成员管理权限；移除、降权或停用负责人前必须完成交接。跨部门成员可加入项目，部门名称不决定角色。
- 开发空间按项目和成员唯一分配，工作区是该空间的执行上下文，固定 `owner_user_id` 与 `project_id`。HTTP 先验证所有者，再按操作检查当前项目权限；任务、附件、偏好、会话和 SSE 均受此约束。
- 写请求读取正文后重新检查登录会话、账号状态与权限；Git、克隆和 Codex 等异步等待后的敏感提交再次授权。撤销执行权限会中止准备或请求中断正在执行的轮次，等待引擎确认，不伪造完成；撤销查看权限会关闭订阅。会话查看、启动、续聊、审批和停止使用独立权限。
- 原生 SSE 使用同源 Cookie；连接、事件投递及心跳检查账号和会话。退出、过期、禁用或重置密码后关闭连接。退出登录不停止已授权启动的后台执行。
- 前端使用 Vue Router，统一清理失效账号的请求、页面、草稿、图片预览和订阅；迟到响应不能写入另一个账号。跨标签登录／退出通过浏览器事件通知；登录令牌不存 localStorage。
- 浏览器通知授权等异步流程在开始时记录账号代际，返回后再次核对。个人设置保存与会话重检并发时，旧快照不能覆盖保存结果；同账号切换工作区后，已排队的未读记录保存仍须完成，换账号则停止旧账号队列。

## 设置作用域

| 层级 | 数据 | 权限 |
| --- | --- | --- |
| 个人设置 | Git 账号、通知开关、任务分组、默认模型、思考强度、执行权限 | 本人，适用本人全部工作区 |
| 系统设置 | 成员目录基础地址、环境检测、部门权限上限、账号资格 | 仅管理员修改 |
| 项目设置 | 名称、负责人、Git 仓库地址、初始化命令、TAPD 配置与凭据、提示词模板 | 对应项目配置权限 |

新任务可覆盖个人执行默认值。已启动任务保存实际选择，后续全局设置修改不回写已有任务。通知授权仍属于浏览器设备权限。未读记录按账号和工作区保存于数据库，不混入系统设置。

创建项目直接提交 `remoteUrl`，项目保存唯一的仓库地址，不再引用独立仓库目录。地址只接受不含密码／令牌的 HTTP(S) 或 SSH Git 地址；项目创建只校验输入，不克隆或要求创建者配置 Git 凭据。项目配置权限允许在尚未分配开发空间时修改地址；已有任一空间后锁定仓库身份，未改变地址的普通设置保存仍允许。公开项目 DTO 返回 `remoteUrl` 和 `repositoryEditable`，不返回 `repositoryId` 或独立仓库对象。旧仓库目录页面与 CRUD 接口已删除，不提供兼容路由。

项目创建／更新不接受 `departmentId`，项目 DTO 不含 `departmentId` 或 `department`，列表也不提供创建用的部门目录。项目以稳定 ID 区分，名称允许重复；项目和用户 ID 决定代码路径，名称不参与权限隔离。账号和项目成员的部门信息继续用于授权和权限解释。

新开发空间的固定成员根为 `<memberStorageRoot>/projects/<projectId>/members/<userId>`，每次受理准备使用其 `repository-<准备修订号>` 子目录；相同请求不重复克隆，失败后的新请求使用新目录并保留旧现场，已就绪空间继续使用记录中的仓库路径，任务为 `worktree/<任务前缀>-<12 位任务短标识>`。项目与账号 UUID 决定路径，改名不改路径。基础目录只有系统级一份，普通成员不能覆盖；已记录的仓库、session、分支、Worktree 和 source 身份不迁移或重命名。项目配置更新同步到已发布空间，后续新任务和追加批次读取最新配置，已有任务快照保持不变。

## 个人 Git 账号

- `GitAccountServices` 负责草稿校验、SSH 生成、连接检测与保存；`GitAccountStore` 负责加密和所有者隔离；公开字段由 presenter 构造。
- 账号输入为 `name, authType, host`，与具体项目仓库分离。HTTP 主机使用完整 origin；SSH 使用主机及可选端口。HTTP 使用用户名／密码或令牌，SSH 使用系统生成的 Ed25519 密钥。公开字段不再包含 `remoteUrl`。
- 保存只校验草稿及修订号，不发起网络请求；更新必须提交当前 `revision`。HTTP 编辑省略密码保留原值。连接检测必须选择当前可操作的项目，以该项目真实仓库执行 `git ls-remote`，验证账号归属及主机／协议匹配，网络返回后再次授权；空仓库读取成功不代表可推送。
- `resolveAccountRemote` 统一解析账号对应的连接地址；主机及认证方式一致时保持原地址。Gitee 官方 `gitee.com` 的默认端口、两段仓库路径支持 HTTPS 与 `git@` SSH 等价地址，按个人账号选择传输方式；不推断企业主机、自定义端口、其他 SSH 用户或任意服务的地址映射，不将 HTTPS 降级为 HTTP。连接检测和克隆使用同一解析结果，项目地址保留原值，开发空间保存实际传输地址；后续同步项目设置不改写已准备空间的传输地址。
- `POST /api/account/git-keys` 生成所有者隔离的 24 小时加密草稿，仅返回 `id, publicKey, expiresAt`。SSH 保存提交 `keyDraftId`，成功事务消费草稿；生成或检测失败不替换原密钥。私钥、密码从不进入公开响应。
- `POST /api/account/git-accounts/check` 检测新增草稿，`POST /api/account/git-accounts/:id/test` 检测已保存账号或编辑草稿；均需 `projectId`，不接受客户端指定任意仓库。
- 凭据以 AES-256-GCM 保存；临时私钥目录在 POSIX 限制模式，在 Windows 限制 ACL，操作结束清理。HTTP Basic 凭据通过仅对子进程生效的 Git 配置传递，不进入命令参数、远程 URL 或仓库配置；禁止跨站重定向。HTTP 明文传输有明确风险提示。
- SSH 的 `-F` 指向私钥临时目录内的真实空配置文件，以隔离用户／系统 SSH 配置；不使用 Windows 与 Git 自带 OpenSSH 解释不一致的 `NUL` 或 `/dev/null`。配置文件与私钥同目录、同权限，并随连接或单次 Git 操作一起清理。
- 关联工作区只保存 Git 账号 ID 与远程地址；克隆及 fetch 在确认远端地址未被改写后使用该账号。该工作区 Codex 会话中的 Git 网络操作也使用该账号。HTTP Basic 凭据仅注入对应 Codex 子进程的 Git 配置，并按保存远端的 URL origin 限定；SSH 私钥写入受限临时文件，并在会话客户端关闭时清理。凭据不写入远程 URL 或仓库配置。关联中的账号不能删除。测试不验证推送权限。
- 已被开发空间引用的账号不能删除或改变主机／认证类型；同类型凭据可轮换。提交作者由独立 `authorName`／`authorEmail` 成对配置，绝不从登录名推断。
- Codex 凭据按连接持有；断线后重新读取，旧子进程停止后才清理它的临时文件。工作区没有运行轮次、审批、准备流水线或命令操作时，在下次启动／续聊前检查数据库修订号并重建连接；不打断其他任务，不创建新 session，不自动重放轮次。跨服务更新也由修订号检查发现。
- 隔离的全局 Git 回退配置只保留系统／全局提交身份字段 `user.name/email/useConfigOnly`、`author.name/email`、`committer.name/email`，不导入凭据、HTTP 请求头或 URL 重写；仓库／Worktree 配置保持更高优先级。该身份临时文件不含认证材料，随对应连接清理；没有身份则继续由 Git 明确报错，不使用 Git 登录名冒充提交作者。
- 本次是不兼容重构，旧数据不迁移、不回退，也不自动删除。使用新的数据目录。

## 持久化边界

项目成员获得有效 `code.operate` 授权时幂等分配开发空间，不立即克隆。成员通过项目空间准备接口选择自己的 Git 账号并提交 UUID 请求标识；`ProjectServices` 管理后台连接检测和克隆。发布工作区与空间 ready 状态在同一短事务内提交，再次校验当前成员权限、项目／凭据修订和准备请求。网络和 Git 等待位于事务外。失败保留空间身份和现场，不自动重复相同请求；服务重启只将死亡进程的准备记录标为失败，不重放、不删除目录、不影响其他存活服务。页面断开和退出登录不直接取消已受理准备。

Git 使用 `--progress` 和英文机器环境输出阶段百分比，服务只解析固定阶段名及 0–100 的整数，不存储或返回原始 stderr、远程消息与凭据。百分比是阶段进度而非整体进度；无已知百分比时返回 null。大仓库最长 6 小时，30 分钟无输出超时，输出以流解析而非积累到固定大小缓冲区。

唯一生产存储为 `DATABASE_URL` 指向的 PostgreSQL。Prisma schema 和版本化 SQL 位于 `prisma/`；存储接口全部异步，调用方必须等待授权、写入和关闭。短事务不等待 Git、网络或 Codex 轮次，详见 [PostgreSQL 接入](./postgresql.md)。旧 SQLite 不兼容、不导入、不读取，旧文件留在原处。

- 账号、登录会话、三类设置、工作区、任务身份、来源、状态、需求快照、提示词、工具和会话历史、操作记录、日志、图片及偏好入库。
- 工作区和运行记录包含有约束的身份、归属和查询字段；渠道快照等异构内容保留 JSON 字段。`storage` 拥有 SQL 和格式，其他模块调用存储接口。
- 登录使用 Fastify Cookie/Session/CSRF/限流插件，Session ID 的摘要保存在 PostgreSQL。业务 POST 保留 `x-tapd-token` 请求头作为与当前会话绑定的 CSRF token。
- TAPD session、Git 凭据与 SSH 草稿使用 AES-256-GCM 加密；主密钥来自 `RUNNER_ENCRYPTION_KEY` 或自动生成的 `<RUNNER_DATA_DIR>/secrets/database.key`。主密钥不会与数据库备份打包；已有数据缺失密钥时拒绝启动。应用密钥不传给 Codex／初始化子进程。
- 标准 Agent 通知和执行诊断日志按块保存；会话展示条目幂等保存，并在继续会话和轮次结束时补齐。分页读取数据库，Codex 离线仍可查看已保存历史。历史补齐保留实时更新，独立维护展示顺序。
- 图片 BLOB 是权威数据，本地图片仅是 Codex 所需的缓存，可校验并重建。缓存不能通过符号链接越界；读取图片必须先经过工作区授权。暂存图片 24 小时过期。
- 任务的 `requirements.json` 是 PostgreSQL `run_documents` 中的资源标识，保存来源归属、创建请求指纹及追加批次快照/发送状态，不是生产磁盘 JSON。RunRequirementsStore 在短事务内同时检查当前工作区所有原始运行记录和新归属记录，再原子写入成员与追加快照，覆盖历史单需求和归档任务；无需重写已有来源、会话或路径。素材抓取、Git 和 Codex 等待在事务外。显式文件测试适配使用工作区级短文件锁，旧任务无需预先迁移；永久删除任务同时删除归属文档。
- Git 仓库、Worktree、构建产物、Codex 原生登录和引擎会话资料、必要的执行锁保留文件形式。业务数据库保存其身份和路径，不移动业务 Worktree。
- Web 与 CLI 工作区命令共用数据库，CLI 属于可信服务器运维入口，审计标记 `local_operator`。显式 `--config` 保留配置输入能力，执行记录仍使用数据库。

这些账号权限提供应用内数据隔离。Git、Codex 和初始化命令仍共享服务器系统用户；不将其描述为不互信租户的文件或进程隔离。

## 初始化、升级和种子数据

首次部署先设置独立 `RUNNER_DATA_DIR` 和指向新数据库的 `DATABASE_URL`，然后执行：

```sh
npm ci
npm run build
npm run db:deploy
npm run init:admin
npm start -- --host 127.0.0.1 --port 4317
```

密码交互输入且不回显，不放入命令参数。服务和初始化命令必须使用同一个 `RUNNER_DATA_DIR`；后续成员密码由管理员在页面的「账号管理」中重置。

服务在监听前检查 Prisma 迁移记录、文件校验和及凭据主密钥指纹，再幂等补齐生产默认值。模块导入不连接数据库、不执行迁移。未部署、失败、被修改或高于当前代码版本的迁移都会拒绝启动；不会回退 SQLite、自动重跑任务或执行降级。

运维显式运行 `npm run db:deploy` 部署 `prisma/migrations/` 中的版本化 SQL。已发布迁移不能修改，后续改动添加新迁移；默认值补齐不创建固定密码账号、演示工作区或需求。历史 `src/storage/migrations/` 脚本不参与新部署。

升级前停止旧服务及 CLI，并完成 PostgreSQL 的一致性备份和恢复演练。Prisma 管理迁移互斥，迁移 SQL 使用数据库事务；程序不再建立 SQLite 文件备份或检查旧库升级锁。

备份还需分别保管 `secrets/database.key` 或外部主密钥，以及原 Git／Worktree 和 Codex 引擎资料。恢复时保留原任务身份和记录路径，仅恢复数据库不会重新创建工作目录。

## HTTP 和部署

### 项目生命周期

- 发布版本使用项目权限 `release.manage`，部门限定上限，项目分配授权。需求／Bug 流程是系统设置，仅当前有效系统管理员可以修改和发布；删除项目权限 `workflow.manage`，不允许项目覆盖系统流程。
- 事项绑定项目 `releaseId` 和不可变的系统 `workflowVersionId`，状态为该版本节点 ID。流程草稿保存与发布使用 revision；发布校验唯一初始节点、节点可达且均能到达终态、权限白名单，完成／取消节点禁止开发。所有项目的新事项使用该类型当前系统发布版本，在途事项不切换。
- `/api/system/workflows/:type` 和 `/:type/publish` 由 `SystemWorkflowServices` 复核管理员身份；`GET /api/projects/:id/issue-workflows/:type` 按 `issue.view` 仅返回已发布版本，不公开草稿。旧 `/api/projects/:id/workflows` 管理接口删除，不保留路由别名。系统流程表和版本表不含 projectId。
- 发布版本归档要求所有事项结束且无未结束开发任务。归档后事项编辑、流转、评论、交付、附件及资产关联变更均被后端拒绝；读取和幂等只读复用不改历史。
- `POST /api/projects/:id/tasks` 仅认领／指派待开发任务；按 `issue.assign` 指派有效且有 `session.start` 权限的执行人，无需 Git。任务仅关联同一发布版本的事项。数据库 `issue_development_claims` 的唯一约束和串行化事务防止重复认领。
- `POST /tasks/:taskId/start` 由执行人提交 revision、requestId 与从实时远端列表选择的 baseBranch，持久化启动意图后准备和执行。GET `/api/projects/:id/branches` 使用本人已准备空间的凭据读取 origin，网络返回后复核授权及空间、账号修订号。Git、网络与 Agent 等待均在事务外。
- 完成／取消任务前校验会话互斥、待处理审批、执行器状态及持久状态，再释放活跃认领。已结束任务的原会话仍可读，禁止续聊和审批启动执行。项目 `issue.view` 可查看计划，执行人之外的成员不获得私有 runKey、工作区或会话 ID。
- 新模型不提供旧状态、旧启动接口或旧数据库格式的运行时兼容。已有业务库需先备份并按明确的数据处置方案更新；迁移不会自动删除旧事项和执行记录。

业务接口需要登录，只有静态登录入口和 `/api/auth/session`、登录接口允许匿名访问。`/api/auth/session` 返回登录状态与 CSRF token；已登录时还返回当前账号的公开信息和个人设置，不返回工作区目录或凭据。

未匹配的全局 API 返回 404，不再当作缺少工作区的请求处理。工作区操作使用 `/api/workspaces/:id/...`；输入非法、没有权限和资源不存在分别按既有 400、403、404 规则处理。已删除的目录接口不保留别名或回退。

登录限流必须覆盖所有实际进入登录处理的请求；URL 规范化不能使含点段等变体路径通过未限流的通配路由进入登录流程。

- `/api/auth/login|logout|password`：登录、退出、修改密码。
- `/api/account/settings`：个人设置；`/api/account/git-accounts`：Git 账号维护与连接测试；`/api/account/preferences`：当前成员某工作区的未读记录。
- `/api/admin/accounts`、`/api/admin/departments`：管理员维护账号（包括显示名称）与部门。`POST /api/account/profile` 仅接受当前账号的 `displayName`，返回 `{ user }`，不接受角色、部门、用户名或其他账号标识。
- `/api/projects`：项目列表和创建，创建输入直接包含 `remoteUrl`；`/:id` 更新项目及仓库地址，使用项目修订号防止并发覆盖；`/:id/members`、`/space/prepare`、`/issues`、`/assets`、`/tasks` 等分别管理授权、开发空间与项目协作。项目资源由应用服务复核权限，公开 DTO 不返回成员凭据。
- 事项创建／编辑可随 JSON 提交 `attachments: [{id, name, mimeType, data}]`；`id` 为客户端生成的 UUIDv4，`data` 为严格 base64，正文引用 `/api/projects/:projectId/files/:id`。每个附件 10 MiB、每批最多 20 个且合计 20 MiB；只有这两类 JSON 路由允许 30 MiB 正文。附件与事项事务保存，创建随 `issue.create` 授权，编辑随 `issue.edit` 授权；修订冲突不留下附件。附件 ID 重试只复用同项目、事项、作者和完全相同内容的文件。
- 事项创建可带稳定的 UUIDv4 `requestId`，同作者、项目与原始输入的重复提交复用事项，不重复编号或历史；重复标识改变输入返回 409。正文、附件列表和开发快照继续归事项，资产文件不能混入。
- 图片 DTO 的 `images`／`previewUrl` 由附件魔数验证生成，PNG／JPEG／WebP／GIF 可以通过 `?inline=1` 预览；普通文件及伪图始终作为附件下载。文件读取再次校验资源权限，返回 `nosniff` 和私有无缓存；不信任上传 MIME，不允许内联 SVG／HTML。
- 新 TAPD 事项导入在事务外按渠道白名单下载并验证 PNG／JPEG／WebP，单图最多 10 MiB、每事项最多 20 张、整批图片合计最多 20 MiB；任一图片失败则不保存该批事项。来源快照的 `projectImages` 保存原引用与附件 ID 映射，保留原文；事项、来源和附件在同一事务保存。详情仅映射本事项已验证的文件，开发快照读取同一附件。重复导入保留既有事项、本地修改与历史快照，不自动回填此前漏图的数据。
- 生产 `POST /api/workspaces`、旧个人克隆入口、工作区配置写入和直接 `POST .../runs` 已关闭；项目配置和显式开发任务使用项目 API。
- 仍可用的工作区需求检索 `/requirements`、`/stories` 必须同时满足工作区所有者、会话查看与需求查看权限；渠道查询返回后再次授权。
- `/api/system/settings`：系统级设置；工作区接口保持 `/api/workspaces/:id/...`。
- `/api/system/environment`（GET）：管理员环境检测；`/check`（POST）：查询四种工具的官方更新版本；`/update`（POST/GET）：确认工具更新／读取更新状态。写操作沿用 CSRF 与正文读取后权限复核，异步更新预检结束后再次复核管理员身份。

本机 HTTP 和开发服务器保留 IP/Host/Origin 校验。正式远程部署建议通过 HTTPS 反代，设置 `PUBLIC_ORIGIN=https://coding.example.com` 并将应用绑定 `127.0.0.1`；代理必须保留公开 Host。代理模式仅接受本机代理连接，不信任任意客户端提供的转发头。HTTPS 模式使用 Secure Cookie。

环境更新只接受 `codex`、`npm`、`git`、`node` 与确切稳定版本（Git 支持 Windows 构建后缀），不接受客户端命令或源地址；重新查询最新版本并核对实际 npm 全局入口后才安装。使用 `--engine-strict` 校验目标 Node.js 要求，安装结束复查实际版本；拒绝降级、并发更新和活动任务／克隆。预检与安装期间阻止新业务 POST（认证接口除外），页面离开不取消安装。进程内状态可供页面重新进入时查询；关闭服务等待已开始安装，服务重启后不恢复或重放更新。失败不保证安装器回滚，必须重新检测。Windows 的 Node.js 支持 nvm 1/2 或已登记的 winget 安装，Git 支持 winget 的 Git.Git；先核对当前二进制归属，固定包标识及版本，拒绝缺少对应发行版的安装。nvm 安装后验证目标二进制和默认版本，当前服务仍使用旧进程，状态为 restart-required；新版本不会被当作已运行。无法识别的安装（包括桌面应用内置 Codex）和未接入的系统安装器只禁用更新并说明原因，不提供指引弹窗。不自动提权、重启或重新执行任务；跨 Node.js 主版本变更需重新安装原生依赖后重启。

Vue 页面路径 `/login`、`/password`、`/personal`、`/system`、`/accounts`、`/environment` 支持直接刷新（旧环境检测地址跳转到 `/system?tab=environment`）；系统设置通过「目录设置 / 环境检测」分类切换内容；未知文件路径不回退到页面入口。开发源码访问范围仍受 Vite 文件白名单限制。

## 验证

Jenkinsfile 运行 eslint、Node 测试、`npm run build` 和浏览器脚本。数据库测试使用独立 PostgreSQL 的随机 schema，执行测试使用假 Codex/TAPD 和临时 Git。覆盖成员越权、登录撤销、SSE/图片隔离、完整执行、离线历史、图片缓存重建、迁移版本校验、事务回滚及连接失败，以及开发种子隔离。

执行配置与任务记录采用 [Agent 契约](./agents.md) 的新格式，不提供旧 `codex` 字段回退。Git 账号引用查询使用 `execution.gitAccountId`，会话固定使用记录中的 `agent.provider`。
