## 已核实的现状

- 全局「开发」页已有「独立开发」入口；选择获授权项目后进入个人开发空间。入口代码：`web/src/features/projects/WorkQueue.vue`、`web/src/app/WorkbenchApp.vue`。
- 图 1 的「手动开启」就是独立开发。`ManualDevelopmentStart.vue` 提交 `/projects/:id/tasks/manual`，不要求关联需求、Bug 或版本；项目、标题、开发目标或图片、起始分支仍有实际用途。
- 环境未就绪时需要准备个人 Git 空间。准备环境不会执行 Agent；启动需明确提交。启动结果不明时查询原请求，不重复启动。
- 当前发布交付通过事项接口，且 `PublishDelivery.vue` 要求 `issueId`。因此「独立开发 → 不关联事项的项目交付」尚未打通。

## 三套方向

| 方案 | 主要区别 | 适合场景 | 取舍 |
| --- | --- | --- | --- |
| A · 会话主导（推荐） | 最接近图 2；单层全局导航、宽会话、精简右侧上下文 | 长时间开发、希望保留分支与来源信息 | 右侧仍占约 270–300px；窄屏折叠 |
| B · 任务列表主导 | 开发列表是工作入口；任务内用会话／代码／交付／任务信息页签 | 并行推进多个开发任务、频繁切换 | 上下文需切换页签查看 |
| C · 开发目标主导 | 目标输入作为主要入口；会话单列，辅助信息按需展开 | 独立探索、短任务、追求最大阅读空间 | 关联事项、分支等信息默认收起 |

三套均使用白色、浅冷灰、石墨主按钮及少量紫色。不是三个配色版本，而是三种工作组织方式。

## 每套六张图

1. 开发入口：独立开发与从事项开发清晰并列，最近任务可继续。
2. 独立开发准备：项目、标题、目标／图片、实时起始分支，显式开始。
3. 事项开发准备：已有待开发任务的范围、环境、分支及开始确认。
4. 开发会话：正文、审批、输入、停止和代码入口；独立开发不显示空的关联事项区。
5. 代码查看：累计／本轮变更、文件、差异、返回会话；不自动提交、合并或推送。
6. 整理成果：独立开发可结束个人任务；无事项的项目交付为**拟新增能力**，需随方案确认。

事项链路：事项认领／指派 → 待开发任务 → 整理范围 → 选择分支并明确开始 → 会话 → 代码 → 交付 → 业务验收。前三步沿用现有业务规则。

独立链路：开发 → 独立开发 → 选择项目／准备个人空间 → 填写目标和起始分支 → 明确开始 → 会话 → 代码 → 结束个人任务，或明确分享成果。不要求先创建需求、Bug 或版本。

「独立」指不依赖事项，仍属于一个授权项目及其 Git 仓库；本轮不引入脱离项目的任意目录执行。

## 清理建议（确认后实施）

| 目前内容 | 建议 | 依据与保留边界 |
| --- | --- | --- |
| 全局导航内再次嵌套「需求 × AGENT」工作台、项目名、需求列表与按钮区 | 去掉常驻第二侧栏，使用返回开发／任务切换器 | 释放会话空间；原会话、历史与深链继续可达 |
| 「手动开启」「手动开启开发」等不一致命名 | 统一为「独立开发」 | 明确无需需求或 Bug |
| 独立开发的「任务类型：需求／Bug／其他」 | 从新建界面移除；来源直接显示独立开发 | 该字段当前影响提示词选择；实施时同步处理提示词语义，不能只隐藏字段后保留错误分类 |
| 常驻人工进度下拉、列表人工进度与任务状态重复展示 | 移除会话中的重复编辑入口，统一到开发任务的完成／取消操作 | 先核对现有元数据消费者；事项状态、开发任务状态与 Agent 状态仍独立 |
| 「信息／Git／需求」入口与标题、整理交付重复 | 统一为上下文、代码和一个整理成果入口 | 独立开发展示目标，事项开发展示关联事项 |
| Session UUID、创建时模型／思考强度、Worktree 路径 | 放入「更多 → 诊断信息」 | 排障按需可查，不删除真实记录 |
| 渠道同步「无需同步」、固定运行引擎重复展示 | 移除无信息量的常驻字段 | 渠道历史及身份仍保留；执行引擎通过会话身份识别 |
| 本轮供应商／系统供应商重复文案、两个默认值、常驻设置生效说明 | 归入执行设置；仅配置变化或异常时显示提示 | 保留当前轮与下一轮实际配置区别 |
| 超长原始启动提示词占据首屏 | 首屏呈现目标摘要与来源，完整快照按需展开 | 不裁剪实际发送内容、附件或历史记录 |
| 常驻刷新、连接成功状态与快捷键长文案 | 正常状态精简，断线／失败时保留明确重试 | SSE、重连及输入行为继续有效 |

不能因精简而丢失：图片上传／重试、审批／提问、停止、继续会话、模型与权限选择、归档／恢复、代码查看、所有权校验、未知启动结果检查。

## 待确认的新增业务点

效果图中的「无需事项的项目交付」是提案，现有接口尚不支持。建议让交付记录可直接关联独立开发任务及项目，事项可选；沿用发布权限和明确共享确认。独立成果的项目查看权限、验证人及通过／退回规则需在实施时同步工程契约，不套用不存在的事项状态。

若只需要个人独立开发，可仅保留「结束个人开发」与历史查看，无需新增项目交付模型。效果图将两种结果区分展示，方便选择。
