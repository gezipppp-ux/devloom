# B 方案：统一中性平台

日期：2026-10-13。交付为设计提案：48 页原图、12 张四页总览和可筛选的本地图册。尚未修改应用代码。

## 已确认的方向

不新增“产品经理 / 研发人员”角色，不设置岗位首页、角色视角切换或独立工作台。B 方案的简约白色、单侧导航与轻紫点缀继续保留。产品规划、任务执行和验收是同一平台里的不同工作活动，同一个人可以参与多个环节。

固定主导航：**工作台 / 项目 / 事项 / 开发 / 交付**。个人设置、管理中心属于低频入口。项目资料和项目配置在项目上下文中，避免把全部设置平铺进全局导航。

已有系统管理员 / 普通成员身份继续存在，这是平台管理权限，不是新增的岗位角色。实际操作沿用部门功能上限、项目授权和个人所有者边界。

## 中性的功能组织

| 工作对象 | 入口与主要操作 | 避免混淆 |
| --- | --- | --- |
| 待推进工作 | 统一工作台聚合与我有关的事项、任务、验证请求 | 不按职业决定首页，不用多个岗位切换器 |
| 项目 | 创建、概览、成员、配置、资料、版本 | 项目协作与个人执行空间分别授权 |
| 事项 | 需求／缺陷、描述与标准、讨论、流程、认领指派 | 需求与缺陷共享列表，但保留各自字段与流程 |
| 开发任务 | 任务范围、合并、负责人、个人环境、分支、执行 | 认领、指派、合并、准备环境不自动运行 Agent |
| AI 执行 | 对话、附件、审批、澄清、代码、Git、停止、历史 | 会话与代码属于执行者，协作者不能因能看事项而读取私有会话 |
| 交付与验证 | 发布公开交付、核对标准、通过／退回、版本归档 | Codex 完成不等于任务完成，更不等于业务验收通过 |
| 资料 | 文档、链接、附件、受保护字段、修订 | 普通资料与敏感字段分开授权，秘密不默认展示 |
| 个人与平台设置 | Git、MCP、默认值、通知、安全、账号、部门、供应商、环境、流程 | 个人、项目、全局三种作用域明确区分 |

## 一条完整的协作链路

1. 有权限的参与者创建需求或缺陷，补充图片、目标、验收标准或复现信息。
2. 在同一事项详情讨论、修改，调整优先级和目标版本。
3. 自行认领或指派给具备执行资格的成员，事项进入待开发任务。
4. 执行者整理范围，可合并同版本本人未启动任务，准备个人 Git 和环境。
5. 选择真实远端分支、模型与权限，明确点击“开始开发”。独立开发可以从开发入口直接创建，不强制关联事项或版本。
6. 执行者在自己的 AI 会话中沟通、审批、检查代码与验证结果。
7. 发布项目可见的交付记录，只包含明确选择的说明、附件、提交标识及关联任务；不会公开整段私有会话。
8. 有验收权限的人核对标准，明确通过或填写退回原因。所有未完成事项和任务满足门禁后才能归档版本。

## 工作台如何照顾不同工作活动

- “待推进”：待完善的事项、待指派工作、需要回答的协作问题。
- “处理中”：本人待开发或正在执行的任务，以及与我有关的事项进展。
- “待验证”：当前可访问且需要验证的公开交付。
- 所有人使用相同分组和布局，数据按“与我相关 / 项目范围”等中性筛选展示；按钮是否开放由有效权限决定。
- 上述跨项目聚合、最近访问及待验证列表属于设计新增的聚合能力，需要后续接口支持，不宣称已经实现。

## 页面和状态范围

48 页覆盖桌面主要功能、关键抽屉／确认状态、两张移动端布局。编辑、创建、查看、禁用、错误等共用同一组件规范；图册不是每一种数据组合的穷举。

- 创建与编辑共用布局，明确只读字段、字段错误、未保存草稿和提交状态。
- 列表加载采用骨架，空列表提供一个明确入口，读取失败保留筛选并可重试。
- 权限变化回收敏感内容，给出当前上下文内的返回路径；页面不因错误伪装成功。
- 保存冲突保留草稿并逐字段选择；开始结果不明只查询原请求，不重复派发。
- 审批与澄清靠近当前消息；拒绝与批准明确，未知请求不伪装可批准。
- 归档、恢复、永久删除、清理工作目录分开表达；删除历史与清理文件明确确认，保留执行身份。
- 移动端采用折叠菜单与底部导航，详情正常滚动，固定操作区保留安全间距；图片、附件与长代码区域单独滚动。
- 登录、首次改密和初始化独立于业务导航；认证密钥和一次性凭证不写进示例正文。

## 图片解释与后续实现

所有图片由 gpt-image-2.5-sunburst 生成，使用虚构数据。图中文字及状态标签是视觉示例；实际实现需复用真实枚举、权限和发布流程，不能直接把生图文案当 API 契约。未来重构应保留原账号、项目、会话、分支和 Worktree 身份。

此轮只做视觉与产品结构；未执行真实需求、未调用 TAPD、未变更生产数据。
